# Part 13　アルゴリズム計算量

## 学習目標

- 入力サイズと基本操作を定め、時間計算量と空間計算量を見積もれる。
- Big O、Big Ω、Big Θを、上界・下界・同じ増え方として区別できる。
- 定数、対数、線形、線形対数、二乗、指数、階乗の成長を比較できる。
- 平均計算量と最悪計算量の違い、アルゴリズム選択の理由を説明できる。

## まず直感

入力が10個なら速いプログラムでも、入力が100万個になると使えないことがあります。

処理時間を秒で一度測るだけでは、コンピュータの性能や入力の分布に依存します。

そこで、入力サイズnが増えたとき、操作回数がどのように増えるかを見ます。

この増え方を**計算量**と呼びます。

## 正式な定義

入力サイズnに対する実行時間を `T(n)` とします。

`T(n)=O(g(n))` は、ある定数cとn0が存在して、`n≥n0` で `T(n)≤c g(n)` となることです。

Big Oは漸近的な上界です。

`T(n)=Ω(g(n))` は、ある正の定数cとn0が存在して、`T(n)≥c g(n)` となることです。

Big Ωは漸近的な下界です。

`T(n)=Θ(g(n))` は、O(g(n))かつΩ(g(n))であることです。

つまり、定数倍を除けば同じ増え方です。

## 成長率の比較

| 記法 | 名称 | nが大きいときの特徴 | 例 |
|---|---|---|---|
| `O(1)` | 定数 | 入力に依存しない | 配列の添字アクセス |
| `O(log n)` | 対数 | 半分ずつ減る | 二分探索 |
| `O(n)` | 線形 | 要素を一度見る | 線形探索 |
| `O(n log n)` | 線形対数 | 分割と併合 | Merge Sort |
| `O(n^2)` | 二乗 | 二重ループ | 全ペア比較 |
| `O(2^n)` | 指数 | 選択肢を全列挙 | 部分集合全探索 |
| `O(n!)` | 階乗 | 全順列を列挙 | 巡回順路の全探索 |

`n!` は通常 `2^n` よりさらに速く増えます。

## 最小の具体例

```python
def find_value(a, target):
    for x in a:
        if x == target:
            return True
    return False
```

最悪の場合、n個すべてを見るため時間計算量は `O(n)` です。

追加の変数だけを使うなら、入力配列を除く追加空間は `O(1)` です。

二重ループなら、外側n回、内側n回で最大 `n×n=n^2` 回です。

## 手計算とコードの読み方

```text
for i = 1 ... n:
    for j = 1 ... n:
        1回の比較
```

内側の処理がn回、外側もn回なので `n^2` 回です。

次のコードは、内側の範囲がiに依存します。

```python
for i in range(n):
    for j in range(i):
        work()
```

回数は `0+1+2+...+(n-1)=n(n-1)/2` です。

最高次数だけを残すと `Θ(n^2)` です。

## 平均、最悪、償却

線形探索は、最悪ではn回比較します。

一様にどの位置も同じ確率で探すなら、成功時の平均比較回数は `(n+1)/2` です。

平均が小さくても、遅延の上限が必要なサービスでは最悪計算量が重要です。

動的配列への追加のように、たまに大きなコピーが起きても、長い操作列全体で平均を取ると一操作あたりの償却計算量が `O(1)` になる場合があります。

平均、最悪、償却は別の主張なので、どれを述べているか明記します。

## 再帰と計算量

再帰アルゴリズムは漸化式で表します。

```text
二分探索: T(n)=T(n/2)+O(1) = O(log n)
Merge Sort: T(n)=2T(n/2)+O(n) = O(n log n)
```

入力を半分にしても、コピーや併合がnに比例するなら、全体は対数だけにはなりません。

## 証明の設計と完全な確認

`3n^2+4n+7` が `Θ(n^2)` であることを確認します。

### 上界

`n≥1` なら `4n≤4n^2`、`7≤7n^2` なので、

```text
3n^2+4n+7 ≤ 14n^2
```

です。

したがって `O(n^2)` です。

### 下界

すべてのnで `3n^2+4n+7≥3n^2` です。

したがって `Ω(n^2)` です。

両方が成立するため `Θ(n^2)` です。

## 擬似コードとPython

```text
count_pairs(A):
    count = 0
    for i = 0 ... n-1:
        for j = i+1 ... n-1:
            count += 1
    return count
```

```python
def count_pairs(a):
    count = 0
    for i in range(len(a)):
        for j in range(i + 1, len(a)):
            count += 1
    return count
```

ペアの数は `C(n,2)=n(n-1)/2` なので、時間計算量は `Θ(n^2)`、追加空間は `O(1)` です。

## よくある誤解

- Big Oは常に厳密な実行時間ではなく、漸近上界です。
- `O(n)` と `O(2n)` は同じ漸近クラスですが、実測時間が同じとは限りません。
- ループの回数だけでなく、ループ内の操作の計算量も掛け合わせます。
- 入力の値の大きさと、入力を表すビット長が異なる問題があります。
- 平均計算量がよいことは、すべての入力が速いことを保証しません。

## 演習問題

### ★ 基本

1. 配列の最初の要素を読む操作の計算量を答えてください。
2. 一重ループでn回処理するコードの計算量を答えてください。

### ★★ 標準

3. 三重ループの計算量を求めてください。
4. `T(n)=T(n/2)+1` の計算量を求めてください。

### ★★★ 応用

5. `1+...+n` をループで求める方法と、式 `n(n+1)/2` で求める方法の計算量を比較してください。
6. Merge Sortが `O(n log n)` になる理由を再帰木で説明してください。

### ★★★★ 発展

7. 全部分集合列挙が `2^n`、全順列列挙が `n!` になる理由を数え上げから説明してください。

## 解答と思考プロセス

1. `O(1)` です。
2. `O(n)` です。
3. 各ループが独立にn回なら `O(n^3)` です。
4. 半分になる回数が `log n` なので `O(log n)` です。
5. ループはn回で `Θ(n)`、式は乗算と加算だけなので `Θ(1)` です。
6. 各階層の併合コストがn、階層数が `log n` なので `n log n` です。
7. 各要素を入れる・入れないの2択がn回あるため `2^n`、n個を最初の位置から順に選ぶため `n!` です。

## 専門家の見方

### このセクションの読み方

ここでは、計算量を公式の暗記ではなく、問題をどの規模まで扱えるかを説明するための共通言語として捉えます。

以下は多くの専門家が議論の出発点として共有する共通土台であり、すべての問題で同じ設計判断をするという意味ではありません。

理論的に確定した定義と、実務でのアルゴリズム選択を分けて読み、どの前提を変えると結論が変わるかを確認してください。

### 5つの中核的なメンタルモデル

1. **漸近的な成長率はスケールを見るためのレンズである**。

計算量は、入力サイズnが大きくなったときの操作数の増え方を、定数倍や低次項を抽象化して表します。

境界条件は、漸近記法が十分大きいnを対象にすることであり、小さなnでの定数、キャッシュ、実装言語、入出力時間を正確に予測する記法ではありません。

数え上げの和や再帰の深さから成長率を導き、グラフの頂点数や辺数を入力サイズとしてアルゴリズムを比較する点で、前の章と接続します。

コードでは、入力の大きさを何として数えるかを先に固定し、二重ループや再帰木が探索空間をどのように広げるかを読むために使います。

現実のモデルでは、nが十倍になったときに処理が何倍になるかを予測する道具であり、単一のベンチマークの代用品ではありません。

2. **入力の符号化とコストモデルが、同じ問題の見え方を変える**。

計算量の入力サイズは、配列の要素数だけでなく、数値を表すビット数やグラフを表すデータ量として定義できます。

境界条件は、値nそのものを一単位とみなすモデルと、nを二進表現した長さを測るモデルが異なることです。

整数論の計算や暗号では、巨大な数の四則演算を一回と数えるか、ビット操作まで展開するかで計算量の主張が変わります。

コードでは、固定長整数、任意精度整数、文字列、ストリーム入力を同じコストとして扱わないことが重要です。

現実のモデルでは、メモリ容量、通信量、データベースアクセス、電力などを独立した資源として数えると、時間だけでは見えない設計上の制約を表現できます。

3. **最悪、平均、償却は異なる保証の種類である**。

最悪計算量はすべての入力に対する上限、平均計算量は入力分布を仮定した期待値、償却計算量は操作列全体で高価な操作をならした一操作あたりの評価です。

境界条件は、平均計算量には分布の仮定が必要であり、償却計算量は一回ごとの遅延上限を保証しないことです。

確率の章の期待値や、データ構造の操作列の分析と接続し、同じアルゴリズムに複数の計算量の顔があることを理解します。

コードでは、入力の順序、乱数、ハッシュ衝突、動的配列の拡張など、どの条件が評価を変えるかを明記します。

現実のモデルでは、応答時間の上限が必要な制御系と、平均スループットを重視するバッチ処理で、採用すべき保証が変わります。

4. **還元は問題の難しさを移し替える翻訳である**。

問題Aを問題Bへ効率よく変換できれば、Bを解く方法からAを解く方法を構成できるため、アルゴリズムの存在や困難さを比較できます。

境界条件は、変換自体の計算量と、判定問題か最適化問題か、解の復元まで含むかを確認することです。

論理のSAT、グラフの到達可能性、発展章のNP完全性は、問題の表面ではなく構造を比較するという点で接続します。

コードでは、入力変換、サブルーチン呼び出し、出力の復元を別々に実装し、変換が探索空間を指数的に膨らませていないかを検査します。

現実のモデルでは、既存のソルバーやサービスへ問題を翻訳する設計が可能になりますが、翻訳後の制約が元の目的を保つかを検証する必要があります。

5. **計算資源の評価は、一つの順位表ではなくトレードオフの地図である**。

時間、追加空間、通信量、近似誤差、前処理時間、更新コストは別々の資源であり、同時に最小化できるとは限りません。

境界条件は、入力を保存する空間を含めるか、前処理を一度だけ払うか、誤差を許すかで比較の意味が変わることです。

再帰、グラフ、確率、最適化の各章と接続し、時間と空間の交換や、正確さと処理可能性の交換を明示します。

コードでは、メモ化で時間を空間に移す、ストリーミングで空間を抑える、近似で探索を止めるといった設計を、計算量と品質の組として評価します。

現実のモデルでは、許容遅延、メモリ上限、誤差予算、運用費用を先に置き、その制約内で最適な資源配分を探します。

### 3つの代表的な対立軸

#### 対立軸1: 厳密解と近似解

立場Aは、目的関数の最適値や判定結果を厳密に求める立場です。

立場Aの最も強い主張は、制約を満たす最適性を証明でき、監査、法的判断、安全限界のように誤差の意味を許せない場面で解釈がぶれないことです。

立場Bは、許容誤差や近似比を明示して、厳密解より短い時間や少ない資源で解を求める立場です。

立場Bの最も強い主張は、候補数が指数的に増える問題でも、品質保証を残しながら現実的な規模へ到達できることです。

どの条件で選択が変わるかは、誤差の上限を証明できるか、最適性の価値が計算費用を上回るか、入力規模と締切がどれほど厳しいかで決まります。

近似解が常に実用的に優れるわけではなく、近似比、データ分布、評価指標、後段の意思決定まで含めて比較します。

#### 対立軸2: 最悪保証と平均性能

立場Aは、入力分布を信頼せず、最悪の場合の時間や空間を上限として設計する立場です。

立場Aの最も強い主張は、攻撃的な入力や異常な入力でもサービス限界を説明でき、遅延や資源枯渇のリスクを抑えられることです。

立場Bは、現実に現れる入力分布をモデル化し、期待性能や典型的なスループットを重視する立場です。

立場Bの最も強い主張は、極端に稀な入力のために通常時の性能や実装の単純さを犠牲にせず、実測に近い設計判断ができることです。

どの条件で選択が変わるかは、入力分布を監視して更新できるか、最悪ケースが攻撃や障害として現実的か、1回の遅延と長期平均のどちらが事業要件かで決まります。

平均が速いという理由だけで最悪の遅延を無視することも、起こり得ない入力に過剰な費用を払うことも、計算量の主張を取り違えています。

#### 対立軸3: 中央集権型と分散型

立場Aは、一つのノードが全データと全体状態を管理し、計算量と正しさを一か所で制御する立場です。

立場Aの最も強い主張は、全体を見た最適化、決定の再現性、障害原因の追跡を実装しやすく、通信による不整合を減らせることです。

立場Bは、複数ノードへ計算とデータを分け、局所処理と通信で全体の処理能力や可用性を得る立場です。

立場Bの最も強い主張は、データ量や利用者数が一台の資源を超えても水平に拡張でき、単一障害点を減らせることです。

どの条件で選択が変わるかは、通信量と同期遅延、分割可能性、整合性要件、障害モデル、データを集約してよいかで決まります。

分散化すると計算が単純にノード数倍速くなるわけではなく、通信、複製、調整、故障時の再計算が新しい計算量になります。

### 理解の深さを見分ける10の質問

1. `O(n log n)` と書かれた二つの実装について、どの入力サイズとコストモデルなら一方が遅くなり得るかを、定数とメモリアクセスを含めて説明してください。

2. 数値nを一つの機械語整数として扱う場合と、nのビット長を入力サイズとする場合で、同じアルゴリズムの計算量の説明をどのように言い換えますか。

3. `T(n)=T(n-1)+1` と `T(n)=T(n/2)+1` の境界条件と再帰の停止を示し、なぜ成長率が異なるのかを説明してください。

4. 平均計算量が `O(1)` でも最悪計算量が大きくなるデータ構造の例を作り、どの入力分布を仮定したかを明記してください。

5. 動的配列の追加操作について、単発のコストと償却コストを区別し、どの操作列なら償却の説明が崩れるかを検討してください。

6. 同じ道路グラフを最短経路問題と最大流問題へ翻訳するとき、頂点、辺、重み、目的関数のどれを変える必要がありますか。

7. ある指数時間アルゴリズムを、入力の半分だけに適用する前処理で高速化できると主張されたとき、全体の計算量をどのように検証しますか。

8. 厳密解を返すアルゴリズムと近似解を返すアルゴリズムを、誤差、計算時間、メモリ、最悪保証の四つの軸で比較する表を作ってください。

9. 中央集権型の計算を分散化したとき、ノード数以外に増えるコストを、通信、同期、複製、故障処理に分けて見積もってください。

10. 利用者数が十倍になった実サービスを想定し、入力サイズ、許容遅延、最悪ケース、平均分布、品質指標のどれを再定義すべきかを選び、その理由を述べてください。
