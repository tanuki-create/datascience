# Part 13　アルゴリズム計算量

## 学習目標

- 入力サイズと基本操作を定め、時間計算量と空間計算量を見積もれる。
- Big O、Big Ω、Big Θを、上界・下界・同じ増え方として区別できる。
- 定数、対数、線形、線形対数、二乗、指数、階乗の成長を比較できる。
- 平均計算量と最悪計算量の違い、アルゴリズム選択の理由を説明できる。

## まず直感

入力が10個なら速いプログラムでも、入力が100万個になると使えないことがあります。

処理時間を秒で一度測るだけでは、コンピュータの性能や入力の分布に依存します。

そこで、入力サイズnが増えたとき、操作回数がどのように増えるかを見ます。

この増え方を**計算量**と呼びます。

## 正式な定義

入力サイズnに対する実行時間を `T(n)` とします。

`T(n)=O(g(n))` は、ある定数cとn0が存在して、`n≥n0` で `T(n)≤c g(n)` となることです。

Big Oは漸近的な上界です。

`T(n)=Ω(g(n))` は、ある正の定数cとn0が存在して、`T(n)≥c g(n)` となることです。

Big Ωは漸近的な下界です。

`T(n)=Θ(g(n))` は、O(g(n))かつΩ(g(n))であることです。

つまり、定数倍を除けば同じ増え方です。

## 成長率の比較

| 記法 | 名称 | nが大きいときの特徴 | 例 |
|---|---|---|---|
| `O(1)` | 定数 | 入力に依存しない | 配列の添字アクセス |
| `O(log n)` | 対数 | 半分ずつ減る | 二分探索 |
| `O(n)` | 線形 | 要素を一度見る | 線形探索 |
| `O(n log n)` | 線形対数 | 分割と併合 | Merge Sort |
| `O(n^2)` | 二乗 | 二重ループ | 全ペア比較 |
| `O(2^n)` | 指数 | 選択肢を全列挙 | 部分集合全探索 |
| `O(n!)` | 階乗 | 全順列を列挙 | 巡回順路の全探索 |

`n!` は通常 `2^n` よりさらに速く増えます。

## 最小の具体例

```python
def find_value(a, target):
    for x in a:
        if x == target:
            return True
    return False
```

最悪の場合、n個すべてを見るため時間計算量は `O(n)` です。

追加の変数だけを使うなら、入力配列を除く追加空間は `O(1)` です。

二重ループなら、外側n回、内側n回で最大 `n×n=n^2` 回です。

## 手計算とコードの読み方

```text
for i = 1 ... n:
    for j = 1 ... n:
        1回の比較
```

内側の処理がn回、外側もn回なので `n^2` 回です。

次のコードは、内側の範囲がiに依存します。

```python
for i in range(n):
    for j in range(i):
        work()
```

回数は `0+1+2+...+(n-1)=n(n-1)/2` です。

最高次数だけを残すと `Θ(n^2)` です。

## 平均、最悪、償却

線形探索は、最悪ではn回比較します。

一様にどの位置も同じ確率で探すなら、成功時の平均比較回数は `(n+1)/2` です。

平均が小さくても、遅延の上限が必要なサービスでは最悪計算量が重要です。

動的配列への追加のように、たまに大きなコピーが起きても、長い操作列全体で平均を取ると一操作あたりの償却計算量が `O(1)` になる場合があります。

平均、最悪、償却は別の主張なので、どれを述べているか明記します。

## 再帰と計算量

再帰アルゴリズムは漸化式で表します。

```text
二分探索: T(n)=T(n/2)+O(1) = O(log n)
Merge Sort: T(n)=2T(n/2)+O(n) = O(n log n)
```

入力を半分にしても、コピーや併合がnに比例するなら、全体は対数だけにはなりません。

## 証明の設計と完全な確認

`3n^2+4n+7` が `Θ(n^2)` であることを確認します。

### 上界

`n≥1` なら `4n≤4n^2`、`7≤7n^2` なので、

```text
3n^2+4n+7 ≤ 14n^2
```

です。

したがって `O(n^2)` です。

### 下界

すべてのnで `3n^2+4n+7≥3n^2` です。

したがって `Ω(n^2)` です。

両方が成立するため `Θ(n^2)` です。

## 擬似コードとPython

```text
count_pairs(A):
    count = 0
    for i = 0 ... n-1:
        for j = i+1 ... n-1:
            count += 1
    return count
```

```python
def count_pairs(a):
    count = 0
    for i in range(len(a)):
        for j in range(i + 1, len(a)):
            count += 1
    return count
```

ペアの数は `C(n,2)=n(n-1)/2` なので、時間計算量は `Θ(n^2)`、追加空間は `O(1)` です。

## よくある誤解

- Big Oは常に厳密な実行時間ではなく、漸近上界です。
- `O(n)` と `O(2n)` は同じ漸近クラスですが、実測時間が同じとは限りません。
- ループの回数だけでなく、ループ内の操作の計算量も掛け合わせます。
- 入力の値の大きさと、入力を表すビット長が異なる問題があります。
- 平均計算量がよいことは、すべての入力が速いことを保証しません。

## 演習問題

### ★ 基本

1. 配列の最初の要素を読む操作の計算量を答えてください。
2. 一重ループでn回処理するコードの計算量を答えてください。

### ★★ 標準

3. 三重ループの計算量を求めてください。
4. `T(n)=T(n/2)+1` の計算量を求めてください。

### ★★★ 応用

5. `1+...+n` をループで求める方法と、式 `n(n+1)/2` で求める方法の計算量を比較してください。
6. Merge Sortが `O(n log n)` になる理由を再帰木で説明してください。

### ★★★★ 発展

7. 全部分集合列挙が `2^n`、全順列列挙が `n!` になる理由を数え上げから説明してください。

## 解答と思考プロセス

1. `O(1)` です。
2. `O(n)` です。
3. 各ループが独立にn回なら `O(n^3)` です。
4. 半分になる回数が `log n` なので `O(log n)` です。
5. ループはn回で `Θ(n)`、式は乗算と加算だけなので `Θ(1)` です。
6. 各階層の併合コストがn、階層数が `log n` なので `n log n` です。
7. 各要素を入れる・入れないの2択がn回あるため `2^n`、n個を最初の位置から順に選ぶため `n!` です。
