# Part 12　有限状態機械とオートマトン

## 学習目標

- 状態、入力、遷移、受理状態を使って有限状態機械を定義できる。
- DFAとNFAの違いを説明できる。
- 正規表現と正規言語の関係を、簡単な例で追跡できる。
- 字句解析、通信プロトコル、UI状態管理を状態機械としてモデル化できる。

## まず直感

自動販売機は、投入金額と選択ボタンに応じて状態を変えます。

「0円」「100円」「200円」「商品購入可能」のような状態を持ち、コインやボタンを入力として遷移します。

状態機械は、履歴をすべて保存する代わりに、将来の動作に必要な情報だけを状態へ要約します。

ログイン画面の「未入力」「入力中」「認証成功」「ロック中」も同じ構造です。

## 正式な定義

**DFA（決定性有限オートマトン）**は、五つ組 `(Q,Σ,δ,q0,F)` です。

- Q：有限個の状態集合。
- Σ：入力アルファベット。
- δ：`Q×Σ→Q` の遷移関数。
- q0：初期状態。
- F：受理状態の集合。

入力文字列を左から一文字ずつ読み、最後の状態がFに属せば受理します。

**NFA（非決定性有限オートマトン）**は、一つの状態と入力から複数の遷移先を持てます。

NFAは、可能な経路の少なくとも一つが受理状態へ到達すれば受理します。

DFAとNFAは表現力の点では同じ正規言語を認識しますが、状態数や実装方法が変わることがあります。

## 最小の具体例

0と1からなる文字列で、「末尾が01」のものを受理するDFAを考えます。

```text
q0 --0--> q1 --1--> q2*
 |         |          |
 1         0          0,1
 |         v          v
 └─────── q0 <────── q2*
```

`q0` は末尾が条件に近づいていない状態、`q1` は直前に0を読んだ状態、`q2`は末尾が01の状態です。

実際にはq2から0を読めばq1、1を読めばq0など、すべての入力に遷移を定義します。

## 手計算

入力 `1101` を読むとします。

```text
開始 q0
1: q0 → q0
1: q0 → q0
0: q0 → q1
1: q1 → q2
```

最後がq2なので受理します。

入力 `1100` なら最後はq1で、受理しません。

## 正規表現と正規言語

DFAやNFAが受理できる文字列の集合を正規言語と呼びます。

正規表現 `0*1` は、「0を0回以上並べた後に1が一つ来る」文字列を表します。

`0001` は一致しますが、`0010` は一致しません。

実際の正規表現エンジンには、バックトラッキングや拡張機能があり、形式言語としての正規表現と完全に同じ挙動とは限りません。

## NFAからDFAへの考え方

NFAが複数の状態にいられると考え、その状態集合全体をDFAの一状態にします。

この方法を部分集合構成と呼びます。

NFAの状態数がnなら、DFAの状態数は最大で `2^n` になる可能性があります。

表現は簡潔になっても、決定化で状態数が増える点が重要です。

## 証明の設計と完全な証明

文字列の先頭から決められた有限個の記号を読むDFAは、入力を読み終えた時点で必ず高々一つの状態にいます。

### 何を示すか

決定性という性質が、遷移関数の定義から出ることを示します。

### 完全な証明

DFAの遷移関数は `δ:Q×Σ→Q` です。

関数は、各入力対 `(q,a)` に対して出力状態を一つだけ割り当てます。

したがって現在状態qと次の入力aが決まれば、次の状態δ(q,a)は一意です。

文字列を一文字ずつ読むたびにこの一意な遷移を適用するため、入力全体を読んだ後の状態も一意です。

## 擬似コードとPython

```text
accepts(machine, word):
    state = machine.start
    for symbol in word:
        state = machine.delta[state][symbol]
    return state in machine.accepting
```

```python
def accepts(delta, start, accepting, word):
    state = start
    for symbol in word:
        state = delta[state][symbol]
    return state in accepting

delta = {
    "q0": {"0": "q1", "1": "q0"},
    "q1": {"0": "q1", "1": "q2"},
    "q2": {"0": "q1", "1": "q0"},
}
assert accepts(delta, "q0", {"q2"}, "1101")
```

入力長をnとすると、DFAのシミュレーションは `O(n)` 時間、状態一つだけを持つため追加空間は `O(1)` です。

## 応用

- 字句解析：識別子、数値、コメントなどのトークンを認識する。
- コンパイラ：文字列をトークン列へ分解する。
- 通信プロトコル：接続前、接続中、認証済み、切断などの手順を制約する。
- UI状態管理：画面の状態とイベントによる遷移を管理する。
- 入力検証：メールアドレスや識別子の形式を限定的に検査する。

## よくある誤解

- NFAは「ランダムに一つを選ぶ機械」ではなく、受理可能な経路の存在を判定する数学モデルです。
- 正規表現は文字列検索の便利な記法ですが、実装によって使える拡張が違います。
- 状態を増やせば、どんな長期記憶も有限状態で表せるわけではありません。
- DFAの遷移を未定義にすると、完全なDFAの定義から外れるため、拒否用のsink状態を加えることがあります。
- UIの状態を一つの真偽値で表すと、同時にあり得ない状態が混ざることがあります。

## 演習問題

### ★ 基本

1. DFAの五つ組の各要素の意味を説明してください。
2. `0*1`に一致する文字列を二つ、しない文字列を二つ挙げてください。

### ★★ 標準

3. 末尾が0の二進文字列を受理するDFAの状態を考えてください。
4. 文字列`0101`を上のDFAで手計算してください。

### ★★★ 応用

5. NFAがDFAより簡潔に書ける例を、複数の受理経路という観点で説明してください。
6. UIの「未保存」「保存中」「保存済み」「エラー」を状態機械にしてください。

### ★★★★ 発展

7. 「0と1の個数がともに偶数」のDFAに必要な最小限の状態の意味を説明してください。

## 解答と思考プロセス

1. 状態、アルファベット、遷移関数、初期状態、受理状態です。
2. 一致は`1`,`001`、不一致は`0`,`010`です。
3. 「直前の文字が0か、それ以外か」の二状態を作り、入力の0で0状態、1で非0状態へ遷移します。
4. `q0→q1→q1→q2→q1` となり、末尾が01なら受理するDFAでは最後のq1により拒否します。
5. NFAは「この位置から始まる」「別の位置から始まる」候補を同時に持つように書けます。
   DFAへ変換すると候補集合を一つの状態にまとめるため、状態数が増えることがあります。
6. 保存ボタンは未保存→保存中→保存済み、通信失敗は保存中→エラー、再試行で保存中へ戻すなど、許されたイベントだけに遷移させます。
7. 0の個数の偶奇と1の個数の偶奇を記憶するので、`偶偶、偶奇、奇偶、奇奇`の4状態が必要です。

## この章で学んだこと

オートマトンは、入力を読みながら有限個の状態を更新し、文字列や操作列を判定するモデルです。

## 前の章とのつながり

集合と関数は、状態集合、入力集合、遷移関数の定義に現れます。

- 状態が有限であることの限界を説明できる。
