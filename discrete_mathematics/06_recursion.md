# Part 6 再帰・漸化式

この章では、問題を同じ形の小さい問題へ分ける考え方を学ぶ。

再帰は関数や定義が自分自身と同じ種類の小さい対象を参照する仕組みであり、漸化式は数列の項を以前の項から定める式である。

再帰を正しく使うには、どこで止まるか、問題が本当に小さくなるか、小問題の答えをどう結合するかを確認する。

## 1. 直感

### 1.1 大きな問題を小さな同型問題へ分ける

10枚のカードを処理する代わりに、5枚ずつ処理して結果を合わせる方法を考える。

5枚の処理も、さらに小さなグループへ分けられる。

分けた先でも同じ問題として扱えることが、再帰の使いやすさである。

### 1.2 停止地点を決める

階段の残り段数を1ずつ減らす処理は、残り0段になったら停止する。

この直接答えられる場合を基底条件という。

基底条件がない、または再帰呼び出しが基底条件へ近づかない場合、処理は停止しない。

### 1.3 数列を前の値から作る

最初の値が1で、毎回2を足す数列は、1、3、5、7、…となる。

次の項を前の項から作る規則を、漸化式で表せる。

数列では初期条件が必要であり、漸化式だけでは数列全体が決まらないことがある。

### 1.4 再帰木として見る

一つの問題が二つの小問題へ分かれるなら、呼び出しは木の形になる。

木の深さ、各段の問題数、各ノードの仕事を数えると、計算量を見積もれる。

## 2. 正式定義

### 2.1 再帰的定義

再帰的定義は、基底条件と再帰規則からなる。

基底条件は、これ以上分解せず値を直接定める。

再帰規則は、より小さい対象の値を使って現在の対象を定める。

階乗は、0! = 1、n! = n × (n−1)!（n ≥ 1）で定義できる。

### 2.2 数列と漸化式

数列は、添字nに対応する値を並べたものである。

たとえば a0 = 2、an = 3an−1 + 1（n ≥ 1）は、初期値と漸化式から数列を定める。

a1 = 7、a2 = 22、a3 = 67となる。

漸化式は隣り合う項の関係を示し、一般項はnからanを直接計算する式である。

### 2.3 Fibonacci数列

Fibonacci数列は、

    F0 = 0
    F1 = 1
    Fn = Fn−1 + Fn−2  (n ≥ 2)

と定義する。

先頭は0、1、1、2、3、5、8、13、…である。

直前2項を使うので、初期条件が二つ必要である。

### 2.4 線形漸化式

以前の項の定数倍を足して作る漸化式を線形漸化式という。

an = 3an−1 − 2an−2 は同次線形漸化式である。

an = 2an−1 + 5 は非同次線形漸化式である。

項を二乗したり、二つの項を掛けたりする式は線形ではない。

### 2.5 再帰アルゴリズム

再帰アルゴリズムは、入力を小さくして同じ関数を呼び、基底条件で答えを返す。

検査するときは、停止条件、入力の縮小、結果の結合、重複計算の有無を確認する。

### 2.6 分割統治

分割統治は、問題を小問題へ分割し、小問題を解き、結果を結合する設計である。

Merge Sortは配列を二つに分けて整列し、整列済みの二つをマージする。

二分探索は、中央との比較で不要な半分を捨て、残った半分を同じ方法で調べる。

### 2.7 Master Theoremへの導入

分割統治の時間を、次の形で表すことがある。

    T(n) = aT(n / b) + f(n)

aは小問題の個数、n / bは各小問題のサイズ、f(n)は分割と結合の仕事である。

Master Theoremは、この形を満たす漸化式の増え方を分類する道具である。

n^(log_b a)とf(n)を比較し、再帰部分、各階層の同程度の仕事、結合部分のどれが支配的かを調べる。

厳密な適用には、a ≥ 1、b > 1、f(n)の増え方などの条件がある。

## 3. 最小例

### 3.1 階乗

4!は、4 × 3 × 2 × 1である。

再帰では4 × 3!、3 × 2!、2 × 1!、1 × 0!と書き、0! = 1で止める。

戻るときに1、2、6、24と値が確定する。

### 3.2 数列

a0 = 1、an = an−1 + 2なら、a1 = 3、a2 = 5、a3 = 7である。

初期値と毎回2を足す規則から、列が一意に決まる。

### 3.3 二分探索

昇順の配列 [2, 5, 8, 12, 17]から12を探す。

中央付近の8と比較し、12は右側にあるので左側を捨てる。

残った[12,17]で再び調べる。

毎回の候補数がほぼ半分になる。

### 3.4 Merge Sort

[7, 2, 5, 1]を[7,2]と[5,1]へ分ける。

[7,2]を[7]と[2]へ分けて[2,7]へ戻し、右側も[1,5]へ戻す。

最後に[2,7]と[1,5]をマージして[1,2,5,7]を得る。

## 5. 手計算

### 5.1 Fibonacciの値

F0 = 0、F1 = 1から始める。

F2 = F1 + F0 = 1

F3 = F2 + F1 = 2

F4 = F3 + F2 = 3

F5 = F4 + F3 = 5

したがってF5 = 5である。

### 5.2 線形漸化式

a0 = 1、an = 2an−1 + 3なら、

    a1 = 2 × 1 + 3 = 5
    a2 = 2 × 5 + 3 = 13
    a3 = 2 × 13 + 3 = 29

となる。

### 5.3 二分探索の比較回数

候補数16は、16 → 8 → 4 → 2 → 1と減る。

半分にする操作は4回なので、候補を1個以下にする深さはlog₂16 = 4である。

中央で最初に一致する場合は最良O(1)、最後まで候補を減らす場合は最悪O(log n)である。

### 5.4 Merge Sortの仕事量

入力8個では、分割の段数はlog₂8 = 3である。

各段で全体として8個を調べるため、仕事は各段O(8)である。

一般にT(n) = 2T(n/2) + O(n)なので、O(n log n)になる。

## 6. 誤解

### 6.1 再帰なら必ず速い

再帰は問題を表す方法であり、速さを保証しない。

Fibonacciの単純再帰のように、同じ小問題を繰り返せば指数的に呼び出しが増える。

### 6.2 基底条件があれば必ず止まる

再帰呼び出しが基底条件へ近づくことも必要である。

入力値を増やす再帰や、区間が縮まらない再帰は停止しない。

### 6.3 漸化式と一般項は同じではない

漸化式は項同士の関係であり、一般項はnからanを直接求める式である。

同じ数列を別の形で表しても、両者は別の情報の持ち方である。

### 6.4 二分探索はどの配列にも使える

中央との大小比較で片側を捨てるには、配列が整列済みである必要がある。

未整列配列では、反対側に目的値がないとは判断できない。

### 6.5 Merge SortとQuick Sortの保証は同じである

標準的なMerge Sortは、入力順に関係なく最良、平均、最悪の時間がΘ(n log n)である。

Quick Sortは、平均的なピボットなら期待O(n log n)だが、偏った分割では最悪O(n²)である。

### 6.6 木の探索は常に対数時間である

二分探索木の探索時間は木の高さhに対してO(h)である。

平衡木ならh = O(log n)だが、片側に偏った木ではh = O(n)である。

## 7. 証明段階

### 7.1 再帰アルゴリズムの正しさ

1. 基底条件で返す値が正しいことを確認する。
2. サイズがnより小さい入力では、再帰呼び出しが正しいと仮定する。
3. その仮定を使い、現在の入力の答えを正しく結合できると示す。
4. よって、基底条件から到達するすべてのサイズで正しい。

これは数学的帰納法と同じ構造である。

### 7.2 Fibonacciの重複計算

1. FnはFn−1とFn−2を必要とする。
2. Fn−1を計算する中にもFn−2が現れる。
3. 同じFn−2を別の枝で再計算する。
4. 呼び出し数はC(n) = C(n−1) + C(n−2) + 1に近い増え方をする。
5. そのため単純再帰の時間は指数的に増える。

メモ化を使えば各F(k)を一度だけ計算でき、固定長整数モデルで時間O(n)、空間O(n)になる。

### 7.3 二分探索の計算量

1. 入力サイズを候補数nとする。
2. 一回の比較後、候補は高々n/2個になる。
3. k回後の候補数は高々n / 2^k個である。
4. n / 2^k ≤ 1となるkはceil(log₂n)である。
5. 一回の比較が一定時間なので、最悪時間はO(log n)である。

目的値が最初の中央にある最良時間はO(1)である。

平均時間O(log n)という説明は、目的位置が一様に現れるなどの条件で使う。

### 7.4 Merge Sortの計算量

1. サイズnを二つのサイズn/2へ分ける。
2. 二つを再帰的に処理するので2T(n/2)になる。
3. 整列済みの二つをマージする仕事はO(n)である。
4. よってT(n) = 2T(n/2) + O(n)である。
5. Master Theoremでa=2、b=2、n^(log₂2)=nと比較し、Θ(n log n)になる。

標準的なMerge Sortは、入力の並びに関係なく最良、平均、最悪の時間がΘ(n log n)である。

補助配列を使う場合の追加空間はO(n)である。

### 7.5 Quick Sortの計算量

1. ピボットを選び、要素を小さい側と大きい側へ分ける。
2. 分割は全要素を見るのでO(n)である。
3. ほぼ半分ならT(n) = 2T(n/2) + O(n)であり、期待O(n log n)になる。
4. 最小要素を毎回選ぶとT(n) = T(n−1) + O(n)になる。
5. n + (n−1) + … + 1 = O(n²)なので、最悪時間はO(n²)である。

平均ではなく期待値を述べる場合、ランダムなピボットなどの条件を明記する。

### 7.6 Master Theoremの見方

T(n) = aT(n/b) + f(n)では、深さjにa^j個の問題があり、各問題のサイズはn/b^jである。

葉に到達する深さはlog_b nである。

各深さの仕事を足し、f(n)とn^(log_b a)のどちらが支配的かを比較する。

## 8. CS応用

### 8.1 二分探索

ソート済み配列の範囲を半分ずつ捨てる。

入力サイズnに対して、最良時間は中央一致のO(1)、平均と最悪は、候補がほぼ半分になる条件でO(log n)である。

再帰版の追加空間は再帰の深さに比例し、O(log n)である。

### 8.2 Merge Sort

分割後に全要素をマージするため、入力の並びに関係なくΘ(n log n)の時間保証がある。

追加配列を使う実装では空間O(n)が必要である。

### 8.3 Quick Sort

ピボットで分割し、左右を再帰的に処理する。

ピボット順位が平均的に偏らない条件では期待O(n log n)、毎回片側が空になる条件では最悪O(n²)である。

再帰スタックは平均O(log n)、最悪O(n)である。

### 8.4 木構造探索

一般の木を全探索するなら、節点数nに対する時間は入力形状に関係なくO(n)である。

再帰スタックは木の高さhに対してO(h)である。

二分探索木で値を探すときはO(h)で、平衡ならO(log n)、偏っていれば最悪O(n)である。

### 8.5 動的計画法への接続

再帰木に同じ小問題が何度も現れるなら、その答えを保存して再利用できる。

Fibonacciのメモ化は、再帰の形を保ったまま重複計算を除く例である。

## 9. 数学的説明

### 9.1 再帰の深さと停止

自然数の入力、区間の長さ、木の高さなど、呼び出しごとに小さくなる尺度を定める。

尺度が0や1で基底条件になり、自然数の減少には無限下降がないなら、再帰は有限回で停止する。

### 9.2 線形漸化式の特性方程式

an = 3an−1 − 2an−2にan = r^nの形を仮定すると、

    r² = 3r − 2
    r² − 3r + 2 = (r − 1)(r − 2) = 0

となる。

根が1と2なので、一般解はC + D × 2^nの形になる。

CとDは初期条件から決める。

### 9.3 Fibonacciの増え方

Fibonacci数列の特性方程式はr² = r + 1である。

正の根は黄金比φに等しく、Fnはおおよそφのn乗に比例して増える。

数値の桁数もnとともに増えるため、大きな整数の演算では整数のビット数も計算量に影響する。

### 9.4 再帰木でMerge Sortを見る

T(n) = 2T(n/2) + cnを考える。

根ではcn、次の段では2個がそれぞれc(n/2)の仕事をするので合計cnである。

どの段でも合計仕事はcn、段数はlog₂nである。

したがって全体はcn log₂nに比例する。

### 9.5 Master Theoremの適用範囲

Master Theoremは、すべての漸化式に使える万能公式ではない。

Quick Sortの二つの部分配列の大きさは一般に同じn/bではないため、そのままの形には当てはめられない。

部分問題が重なって共有される場合は、再帰木だけでなくメモ化後の状態数も分析する。

## 10. 擬似コード

### 10.1 階乗

    function factorial(n):
        if n == 0:
            return 1
        return n × factorial(n − 1)

入力n ≥ 0に対して、時間O(n)、再帰スタックO(n)である。

### 10.2 二分探索

    function binary_search(A, target, left, right):
        if left > right:
            return NOT_FOUND
        middle = (left + right) // 2
        if A[middle] == target:
            return middle
        if target < A[middle]:
            return binary_search(A, target, left, middle − 1)
        return binary_search(A, target, middle + 1, right)

前提はAが昇順にソートされていることである。

最良O(1)、平均と最悪O(log n)、追加空間O(log n)である。

### 10.3 Merge Sort

    function merge_sort(A):
        if length(A) <= 1:
            return A
        middle = length(A) // 2
        left = merge_sort(A[0:middle])
        right = merge_sort(A[middle:])
        return merge(left, right)

    function merge(left, right):
        result = empty list
        while left and right are not empty:
            append the smaller first element to result
        append the remaining elements to result
        return result

最良、平均、最悪はΘ(n log n)、補助空間はO(n)である。

### 10.4 Quick Sort

    function quick_sort(A, left, right):
        if left >= right:
            return
        pivot_index = partition(A, left, right)
        quick_sort(A, left, pivot_index − 1)
        quick_sort(A, pivot_index + 1, right)

均等分割の期待条件では期待O(n log n)、最悪はO(n²)である。

### 10.5 木の深さ優先探索

    function dfs(node, target):
        if node is empty:
            return false
        if node.value == target:
            return true
        for child in node.children:
            if dfs(child, target):
                return true
        return false

全節点を訪れる最悪時間はO(n)、追加空間は高さhに対してO(h)である。

## 11. Python

    def factorial(n: int) -> int:
        if n == 0:
            return 1
        return n * factorial(n - 1)

    def fibonacci(n: int) -> int:
        if n <= 1:
            return n
        return fibonacci(n - 1) + fibonacci(n - 2)

    def binary_search(values: list[int], target: int,
                      left: int, right: int) -> int:
        if left > right:
            return -1
        middle = (left + right) // 2
        if values[middle] == target:
            return middle
        if target < values[middle]:
            return binary_search(values, target, left, middle - 1)
        return binary_search(values, target, middle + 1, right)

    def merge(left: list[int], right: list[int]) -> list[int]:
        result = []
        i = j = 0
        while i < len(left) and j < len(right):
            if left[i] <= right[j]:
                result.append(left[i])
                i += 1
            else:
                result.append(right[j])
                j += 1
        result.extend(left[i:])
        result.extend(right[j:])
        return result

    def merge_sort(values: list[int]) -> list[int]:
        if len(values) <= 1:
            return values[:]
        middle = len(values) // 2
        left = merge_sort(values[:middle])
        right = merge_sort(values[middle:])
        return merge(left, right)

    def quick_sort(values: list[int]) -> list[int]:
        if len(values) <= 1:
            return values[:]
        pivot = values[len(values) // 2]
        smaller = [x for x in values if x < pivot]
        equal = [x for x in values if x == pivot]
        larger = [x for x in values if x > pivot]
        return quick_sort(smaller) + equal + quick_sort(larger)

    class Node:
        def __init__(self, value, children=None):
            self.value = value
            self.children = children or []

    def contains(node, target):
        if node is None:
            return False
        if node.value == target:
            return True
        return any(contains(child, target) for child in node.children)

    print(factorial(4))
    print(fibonacci(6))
    print(binary_search([2, 5, 8, 12, 17], 12, 0, 4))
    print(merge_sort([7, 2, 5, 1]))
    print(quick_sort([7, 2, 5, 1, 2]))

このPythonのQuick Sortは理解用に新しいリストを作る実装である。

この実装では、ピボットの順位が入力に対して平均的に偏らない、または入力がランダムな順列であるという条件で期待O(n log n)である。

最悪時間はO(n²)である。

再帰スタックは期待O(log n)、最悪O(n)である。

さらに、各呼び出しがsmaller、equal、largerの新しいリストを作るため、追加空間は均等分割の経路でO(n)、偏った分割が深く続く最悪ケースではO(n²)になり得る。

この空間評価は、配列内で分割する実装の評価とは異なる。

次の木を左の子から深さ優先探索するとき、訪問順と、節点数n、高さhによる計算量を求めよ。

        A
      / | \
     B  C  D
    / \    |
   E   F   G

## 13. 思考プロセス付き解答

ここでは、途中の判断を追跡できる解法の筋道を示す。

### 問1の解答

初期値2から毎回3を足す。

a1 = 5、a2 = 8、a3 = 11である。

### 問2の解答

小さい添字から順に、直前2項を足す。

F2 = 1、F3 = 2、F4 = 3、F5 = 5、F6 = 8である。

### 問3の解答

fib(5)の左枝fib(3)の中にfib(2)が1個ある。

根の右枝にもfib(3)があり、その中にfib(2)が1個ある。

さらにfib(4)の中のfib(2)が1個ある。

したがってfib(2)は3回呼び出される。

同じ値の計算を保存できることが、メモ化の効果である。

### 問4の解答

候補数は32 → 16 → 8 → 4 → 2 → 1と減る。

半分にする操作は5回なので、上限はlog₂32 = 5である。

中央で一致する場合はこれより短いので、これは最悪側の上限である。

### 問5の解答

二つの半分を再帰的に処理し、最後に全要素をマージする。

したがってT(n) = 2T(n/2) + cnである。

再帰木の各段では、部分問題のサイズの合計がnなので、マージの仕事は合計cnである。

段数はlog₂nだから、全体はcn log₂nに比例し、Θ(n log n)である。

標準的なMerge Sortでは入力順に関係なくこの評価になる。

### 問6の解答

最小要素を選ぶと、片側は空で、もう片側にn−1個残る。

よってT(n) = T(n−1) + cnである。

展開するとcn + c(n−1) + … + cとなり、n(n+1)/2に比例する。

したがって最悪時間はO(n²)である。

平均O(n log n)という説明は、ピボットの順位が平均的に偏らない条件でのみ成り立つ。

### 問7の解答

左の子を先に、節点を見つけた時点で訪れる。

訪問順はA → B → E → F → C → D → Gである。

全節点を一度ずつ確認するため、時間はO(n)である。

最深の呼び出し数は高さhに比例するため、追加空間はO(h)である。

## 専門家の見方

### このセクションの読み方

ここでは、再帰や漸化式を個別の公式としてではなく、問題の構造を表すための共通土台として捉える。

「多くの専門家が共有する共通土台」と「代表的な対立軸」を分けることで、数学的に確定した定義と、実装時の選択を混同しないようにする。

### 5つの中核的なメンタルモデル

#### 1. 再帰は「同じ種類の小さい問題」と「停止」を一組で記述する

定義：再帰的な手続きは、基底条件（直接答えられる場合）と、より小さい入力へ移る再帰規則からなる。

境界条件：入力が本当に有限回で基底条件へ到達する尺度を持たなければ、再帰は定義ではなく無限呼び出しになる。

他章との接続：基底条件と縮小を証明の数学的帰納法に対応させると、正しさの主張と停止性の主張を分けて検証できる。

コードや現実のモデル化への意味：関数の引数に「何が小さくなったか」を明示し、ファイル階層や構文木のように部分構造が同じ種類である対象へ適用する。

#### 2. 漸化式は値だけでなく、依存関係と計算量を表す

定義：漸化式は、ある項や問題の答えを、以前の項や小問題の答えから定める関係である。

境界条件：初期条件が不足していたり、添字が過去へ進まなかったりすると、数列や計算量を一意に定められない。

他章との接続：分割統治の `T(n)=aT(n/b)+f(n)` は、答えの漸化式ではなく実行時間の漸化式である。

コードや現実のモデル化への意味：入力サイズ、枝分かれ数、各段の仕事を分離して書くと、実装前に性能の支配要因を見積もれる。

#### 3. 再帰木は、仕事の重複と共有を可視化する

定義：再帰木は、呼び出しを頂点、小問題への分岐を辺として、どの問題が何回現れるかを表す図である。

境界条件：小問題が独立なら木として数えられるが、同じ小問題が複数回現れる場合は、実際の計算は共有を持つ有向非巡回グラフ（DAG）として考える必要がある。

他章との接続：Fibonacciの重複計算は動的計画法へつながり、分割統治では各階層の仕事を足す分析へつながる。

コードや現実のモデル化への意味：ログやキャッシュの設計では、同じキーの計算を再利用するか、独立に繰り返すかを再帰木で比較する。

#### 4. 再帰と反復は、同じ状態遷移を異なる記憶方法で実行できる

定義：反復（ループによる繰り返し）は、更新される状態を明示的に保持し、再帰は呼び出しスタック（未完了の処理を積む領域）に状態を保持する。

境界条件：再帰から反復へ機械的に変換できるのは、戻り道で必要な状態と、分岐の順序を明示的に保存できる場合である。

他章との接続：DFSは再帰とスタックの対応を示し、木の走査では前順・中順・後順の順序が保存すべき状態を決める。

コードや現実のモデル化への意味：深い入力でスタックが不足する環境では、明示的なスタックやループへ移すが、アルゴリズムの不変条件（途中でも保たれる性質）は同じに保つ。

#### 5. トップダウンとボトムアップは、依存関係をたどる方向の違いである

定義：トップダウンは大きな問題から必要な小問題へ進み、ボトムアップは基底となる小問題から依存先の大きな問題へ値を積み上げる。

境界条件：依存関係に閉路がある場合や、必要な順序を一意に決められない場合は、単純なボトムアップ表では処理できず、別の順序付けが必要になる。

他章との接続：メモ化（計算結果を保存して再利用する方法）はトップダウンに、表を埋める動的計画法はボトムアップに近い。

コードや現実のモデル化への意味：必要な状態が少ないときはトップダウンの遅延計算が有利で、ほぼ全状態を使うときはボトムアップの連続したメモリ配置が有利になりやすい。

### 3つの代表的な対立軸

#### 対立軸1: 再帰と反復

この対立は好みではなく、表現の明快さ、スタック使用量、実行環境の制約をどこに置くかという設計上の違いである。

立場A：再帰で、問題の定義とコードの構造を直接対応させる。

立場Aの最も強い主張：木や分割統治のように部分問題が同型なら、再帰は証明の形と実装の形を近づけ、分岐や戻り道の意味を読みやすく保てる。

立場B：反復で、状態と停止条件をループとして明示する。

立場Bの最も強い主張：深い入力でも呼び出しスタックに依存せず、状態を限定すれば追加メモリを抑え、実行系のオーバーヘッドも予測しやすい。

どの条件で選択が変わるか：木の高さや分割の深さが小さく、再帰構造が問題の本質なら再帰を選び、深さが入力に比例する、スタック制限が厳しい、または状態遷移が一方向なら反復を選ぶ。

#### 対立軸2: トップダウンのメモ化とボトムアップの表計算

この対立は、同じ漸化式を解く順番と、未使用状態にも計算資源を払うかというコストモデルの違いである。

立場A：トップダウンで、要求された状態だけを再帰的に計算し、結果をメモ化する。

立場Aの最も強い主張：状態空間が大きくても到達する状態が少ないなら、不要な状態を計算せず、漸化式の定義をそのまま実行できる。

立場B：ボトムアップで、基底状態から依存順に表を埋める。

立場Bの最も強い主張：計算順序、メモリ使用量、ループの回数を明示でき、呼び出しスタックを使わず、連続した配列アクセスを活かしやすい。

どの条件で選択が変わるか：到達状態が疎で依存関係が自然に再帰的ならトップダウンを選び、ほぼ全状態を使う、反復で順序を保証できる、局所性（近いメモリを続けて使う性質）が重要ならボトムアップを選ぶ。

#### 対立軸3: 漸化式を保った計算と閉形式への変換

この対立は、依存関係を検証しやすい表現を残すか、直接計算できる式へ変換して計算回数を減らすかという目的の違いである。

立場A：漸化式と初期条件を保ち、逐次計算または行列累乗などで値を求める。

立場Aの最も強い主張：定義からの導出が透明で、係数や境界条件が変わってもモデルを修正しやすく、整数性や丸めの影響も管理しやすい。

立場B：一般項や閉形式（添字から直接値を出す式）を導出し、必要な項を直接計算する。

立場Bの最も強い主張：多数の添字を何度も問い合わせるとき、依存する全項を順に計算せず、対数時間の累乗法や定数回の式評価へ落とせる場合がある。

どの条件で選択が変わるか：閉形式が導出でき、数値誤差や巨大数の扱いが許容されるなら直接計算を選び、規則が変動する、証明と実装の対応を重視する、厳密な整数値が必要なら漸化式を保つ。

閉形式が常に存在するとは限らず、どの表現が最良かは与えられた漸化式と計算モデルに依存する実務上の選択である。
