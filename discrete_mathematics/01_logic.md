# Part 1　論理

## 学習目標

- 命題の真偽を区別し、論理演算を真理値表で計算できる。
- 「PならばQ」の意味を、必要条件と十分条件の言葉で説明できる。
- 述語と量化記号を読み、量化記号を否定できる。
- 条件式、`boolean`、`assert` と数学論理の対応を説明できる。

## 直感

論理は、文章の印象ではなく、条件が成立しているかを機械的に判定するための言語です。

たとえば「パスワードが正しく、かつアカウントが有効ならログインを許可する」という処理では、二つの条件の両方が必要です。

プログラムはこの条件を真か偽かに変換し、分岐を選びます。

数学では、真または偽のどちらかを持つ文を**命題**と呼びます。

「今日は雨です」は、対象となる日が決まれば命題になります。

「窓を閉めてください」は真偽を判定する文ではないため、命題ではありません。

## 正式な定義

### 命題と真偽値

**命題**とは、真（`True`）または偽（`False`）のいずれか一つに決まる宣言文です。

命題を表す変数には通常 `P`、`Q`、`R` を使います。

### 基本演算

| 記号 | 読み方 | 真になる条件 |
|---|---|---|
| `¬P` | Pでない | Pが偽 |
| `P ∧ Q` | PかつQ | PとQがともに真 |
| `P ∨ Q` | PまたはQ | 少なくとも一方が真 |
| `P ⊕ Q` | PまたはQの一方だけ | 真偽が異なる |
| `P → Q` | PならばQ | Pが真なのにQが偽、という場合以外 |
| `P ↔ Q` | PとQは同値 | PとQの真偽が同じ |

「または」は数学やプログラムでは通常、両方とも真である場合も含みます。

### 含意の真理値表

含意 `P→Q` が偽になるのは、Pが真でQが偽の一行だけです。

| P | Q | `P→Q` |
|---|---|---|
| 偽 | 偽 | 真 |
| 偽 | 真 | 真 |
| 真 | 偽 | 偽 |
| 真 | 真 | 真 |

これは日常語の約束と少し違って見えます。

数学の含意は「Pが成立した場合にQも成立する」という保証を表し、Pが成立しない場合のQを約束しません。

したがって `P→Q` は `¬P∨Q` と論理的に同値です。

### 必要条件と十分条件

`P→Q` のとき、PはQの**十分条件**です。

Pが起きればQが必ず起きるからです。

QはPの**必要条件**です。

Pが起きるにはQが必要だからです。

`P↔Q` なら、PはQの必要十分条件です。

### 述語と量化

変数を含む文 `P(x)` を**述語**と呼びます。

対象が動く範囲を**定義域**または**論議領域**と呼び、`D` で表します。
`∀x∈D, P(x)` は「定義域DのすべてのxについてP(x)が真」を表します。

`∃x∈D, P(x)` は「定義域Dの中に、P(x)を真にするxが少なくとも一つ存在する」を表します。

量化記号を否定するときは、全称と存在を入れ替えます。

```text
¬(∀x∈D, P(x))  ↔  ∃x∈D, ¬P(x)
¬(∃x∈D, P(x))  ↔  ∀x∈D, ¬P(x)
```

## 最小の具体例

`P` を「入力値nは偶数」、`Q` を「nを2で割った余りは0」とします。

整数の範囲では `P↔Q` が成立します。

一方、「nは4の倍数」から「nは偶数」は導けますが、逆は導けません。

したがって「4の倍数」は「偶数」の十分条件であり、「偶数」は「4の倍数」の必要条件です。

## 「PならばQ」の読み方

日常語の「ならば」は、時間の順番や因果関係を含むことがあります。

数学の `P→Q` は、因果関係やPが実際に起きたことを主張していません。

「4の倍数なら偶数」は、4の倍数でない数について何も言いません。

たとえば `n=3` ではPは偽です。

このとき `P→Q` は真と定義されますが、「3は偶数だ」と言っているわけではありません。

「契約の条件Pを満たしたのに、結果Qが起きなかった」ときだけ約束が破られると考えると、真理値表を理解しやすくなります。

## ASCII図解

ド・モルガンの法則を真理値表で確認します。

```text
¬(P ∧ Q)  ↔  ¬P ∨ ¬Q
```

```text
P → Q の判定

P = 真 ───────────────→ Qを調べる
                            │
                            ├─ Q = 真  → 含意は真
                            └─ Q = 偽  → 含意は偽

P = 偽 ── 前件が成立していない ──→ 含意は真
```

必要条件と十分条件の向きは、矢印の左右で確認する。

```text
P  ─────────→  Q
│              │
└─ PはQの      └─ QはPの
   十分条件       必要条件
```

| P | Q | `P∧Q` | `¬(P∧Q)` | `¬P` | `¬Q` | `¬P∨¬Q` |
|---|---|---:|---:|---:|---:|---:|
| 偽 | 偽 | 偽 | 真 | 真 | 真 | 真 |
| 偽 | 真 | 偽 | 真 | 真 | 偽 | 真 |
| 真 | 偽 | 偽 | 真 | 偽 | 真 | 真 |
| 真 | 真 | 真 | 偽 | 偽 | 偽 | 偽 |

左辺と右辺の列がすべて一致するため、二つの式は論理的に同値です。

これは「PかつQではない」と「Pでない、またはQでない」が同じ条件を表すことを示します。

## 途中式を省略しない手計算

### 含意の真偽を計算する

`P=True`、`Q=False` のときに `P→Q` を計算する。

```text
P→Q
⇔ ¬P∨Q
⇔ False∨False
⇔ False
```

含意は前件が真で後件が偽のときだけ偽なので、この組合せでは偽です。

### 量化記号の否定を計算する

「すべての整数 `x` について `x²≥0`」を否定する。

```text
¬(∀x∈Z, x²≥0)
⇔ ∃x∈Z, ¬(x²≥0)       全称を存在へ交換
⇔ ∃x∈Z, x²<0          不等式を否定
```

実数の二乗は0以上なので、最後の命題を真にする整数は存在しない。
したがって元の全称命題は真であり、その否定は偽である。

### 必要条件と十分条件を手計算で確認する

Pを「`n` は4の倍数」、Qを「`n` は偶数」とする。

```text
P: n=4k  （kは整数）
n=4k
 =2(2k)
```

`2k` は整数なので、PならばQです。
よってPはQの十分条件、QはPの必要条件です。

逆向きが成り立たないことは、`n=2` を代入して確認できる。

```text
n=2 は偶数なのでQは真
2=4k を満たす整数kはないのでPは偽
Q→P は 真→偽 となり偽
```

## よくある誤解

- `P∨Q` は「どちらか一方だけ」とは限りません。
- `P→Q` を `Q→P` に入れ替えることはできません。
- `P→Q` から `¬P→¬Q` は導けません。
- 含意を証明するとき、Pが偽の例を調べるだけでは十分ではありません。
- 量化された文では、対象となる集合（定義域）を省略すると意味が変わります。

反例を一つ挙げると、偶数 `P` なら4の倍数 `Q` という含意は偽です。

`n=2` ではPが真、Qが偽になるからです。

## 証明

命題「整数nが4の倍数なら、nは偶数である」を証明します。

### 何を示すか

任意の整数nについて、`4|n` なら `2|n` を示します。

### 使う定義・定理

`4|n` とは、ある整数kを使って `n=4k` と書けることです。

### 方法候補

前提を直接式に置けるので、直接証明が自然です。

対偶を使う必要も、場合分けをする必要もありません。

### 骨格

1. `n=4k` と置く。
2. `n=2(2k)` と変形する。
3. `2k` は整数なので、nは偶数である。

### 完全な証明

`n` を4の倍数とする。

整除の定義より、ある整数kが存在して `n=4k` と書ける。

すると `n=4k=2(2k)` である。

`2k` は整数なので、整除の定義よりnは2の倍数、つまり偶数である。

## プログラミング・アルゴリズム・DB等との関係

数学の `∧`、`∨`、`¬` は、多くの言語の `and`、`or`、`not` に対応します。

```python
def can_login(password_ok: bool, account_active: bool) -> bool:
    return password_ok and account_active

assert can_login(True, True) is True
assert can_login(True, False) is False
```

`if` は条件が真のときに処理を選びます。

`assert` は、ある条件が真であるべきだという仕様を実行時に確認します。

ただし、プログラムの短絡評価では、数学の真理値表と違って右側を評価しない場合があります。

この違いは、式の真偽と評価手順を区別する例です。

アルゴリズムの仕様は、「入力が前提条件を満たすなら、出力が事後条件を満たす」という含意で書けます。
ループでは、各反復の前後で真のまま保たれるループ不変条件を置き、終了時に結論を導きます。

データベースの `WHERE` も論理式です。

```sql
WHERE is_member = TRUE
  AND (role = 'admin' OR role = 'owner')
```

これは「会員であり、かつ管理者または所有者」という命題を表す。
ただしSQLの `NULL` は真偽に加えて不明を生むため、二値論理の真理値表をそのまま適用してはいけない。
`NULL` の有無を判定するときは `IS NULL` や `IS NOT NULL` を使う。

## 数学的説明 → 擬似コード → Python

### 条件を満たすときだけ許可する

数学的説明では、

```text
許可 ⇔ 年齢が18以上 ∧ 会員である ∧ 支払い済みである
```

と書く。

擬似コードでは次のようになる。

```text
入力 age, is_member, has_paid
if age >= 18 かつ is_member かつ has_paid ならば
    Trueを返す
else
    Falseを返す
```

Pythonでは、比較と `and` を対応させる。

```python
def can_purchase(age, is_member, has_paid):
    return age >= 18 and is_member and has_paid


print(can_purchase(20, True, True))
print(can_purchase(20, True, False))
print(can_purchase(17, True, True))
```

出力は `True`、`False`、`False` になる。

### 含意を擬似コードとPythonへ変換する

数学では `P→Q` は `¬P∨Q` と同値です。

```text
入力 P, Q
if P が偽 または Q が真 ならば
    Trueを返す
else
    Falseを返す
```

```python
def implies(p, q):
    return (not p) or q


for p in (False, True):
    for q in (False, True):
        print(p, q, implies(p, q))
```

`P=True` かつ `Q=False` の組だけが `False` になる。

## 演習問題

### ★ 基本

1. 「7は素数である」は命題ですか。
2. `P=True`、`Q=False` のとき、`¬P`、`P∧Q`、`P∨Q`、`P→Q` を求めてください。

### ★★ 標準

3. 「nが6の倍数ならnは3の倍数」を、必要条件と十分条件の言葉で説明してください。
4. `¬(P∨Q)` と同値な式を書いてください。

### ★★★ 応用

5. `∀x∈Z, x^2≥0` の否定を書いてください。
6. 「すべてのユーザーが有効なメールアドレスを持つ」の否定を、自然言語と量化記号で書いてください。

### ★★★★ 発展

7. `P→Q` と `¬Q→¬P` が同値であることを真理値表で確認してください。

## 思考プロセス付き解答

1. 真偽が決まる宣言文なので命題です。
2. `¬P=False`、`P∧Q=False`、`P∨Q=True`、`P→Q=False` です。
   含意は前件が真で後件が偽のときだけ偽です。
3. `n` が6の倍数であることが十分条件、nが3の倍数であることが必要条件です。
   逆向きは、3の倍数でも6の倍数とは限らないため成立しません。
4. ド・モルガンの法則から `¬P∧¬Q` です。
5. 「ある整数xが存在して `x^2<0`」です。
   実際にはそのような整数は存在しないため、元の全称命題は真です。
6. 「有効なメールアドレスを持たないユーザーが少なくとも一人存在する」です。
   `¬(∀u∈Users, Valid(u)) ↔ ∃u∈Users, ¬Valid(u)` です。
7. まず `P,Q` の4通りを並べ、左辺と右辺を別列で計算します。
   4行すべて一致すれば同値です。

   | P | Q | `P→Q` | `¬Q` | `¬P` | `¬Q→¬P` |
   |---|---|---:|---:|---:|---:|
   | 偽 | 偽 | 真 | 真 | 真 | 真 |
   | 偽 | 真 | 真 | 偽 | 真 | 真 |
   | 真 | 偽 | 偽 | 真 | 偽 | 偽 |
   | 真 | 真 | 真 | 偽 | 偽 | 真 |

   `P→Q` と `¬Q→¬P` の列が一致するため、二つは同値です。

## 専門家の見方

### このセクションの読み方

ここでいう「共通土台」は、すべての論理学者や設計者が同じ論理体系を採用するという意味ではなく、議論の対象、真偽の条件、証明の規則を切り分けるために多くの専門家が共有する出発点です。

真理条件（ある解釈や状況で文が真になる条件）と証明可能性（決められた規則で式から導ける性質）は関連しますが、同じ概念ではありません。

以下の対立軸では、理論的に確定した定義と、目的に応じて選ぶ論理体系や実装を混同しないでください。

個別の未解決問題に決着を与えるとは主張しません。未解決の論点は未解決と明記し、採用する体系の定義と実務上の選択を分けて扱います。

### 5つの中核的なメンタルモデル

1. **論理式は構文と意味の二層を持つ**：構文は記号をどの規則で組み合わせたか、意味はその式がどの解釈で真になるかを表します。
式が正しく書けることは真であることを保証せず、真理値表は二値命題論理の意味を調べる道具であって、証明規則そのものではありません。
この区別は、集合の所属条件、プログラムの条件式、データベースの検索条件へ接続し、コードでは構文解析に成功した式を実行時の値や副作用と別に検査する設計になります。

2. **含意は原因の物語ではなく反例の境界である**：`P→Q` が偽になるのは、Pが真なのにQが偽である場合だけであり、PがQを時間的に引き起こすという意味は論理式だけからは出ません。
この境界条件を覚えると、必要条件と十分条件、対偶、仕様違反を同じ形で読み替えられます。
コードでは事前条件と事後条件、現実のモデル化では「この条件を満たしたのに結果が満たされない」ケースを探す設計になります。

3. **量化には領域と作用範囲がある**：全称量化と存在量化は、どの対象を走査するかという領域と、量化記号がどの式にかかるかというスコープ（作用範囲）を伴います。
「すべて」と「ある」の順序を変えると主張が変わり、空集合や空の領域では直感と異なる真偽になることがあります。
集合の部分集合、アルゴリズムの全入力保証、データベースの条件検索へ接続し、コードではループ範囲、`any`、`all` の仕様を明示する境界になります。

4. **証明は証明可能性を作る規則付きの計算である**：証明は、仮定、定義、既知の定理、推論規則を有限回適用して、結論へ至る導出を構成します。
ある解釈で真であることと、選んだ公理系で証明できることは区別され、体系の表現力や無矛盾性などの前提が変われば証明可能な範囲も変わります。
このモデルは、集合の等式証明、プログラム検証、型検査に接続し、コードではテストによる反例探索と形式的保証を別の成果として扱う理由になります。

5. **論理は合成可能な仕様言語である**：小さな命題の真理条件を固定すると、否定、論理積、論理和、量化によって大きな仕様の意味を段階的に組み立てられます。
ただし、短絡評価、未定義値、例外、副作用を持つプログラムの条件式は、純粋な真理関数と同じ挙動をしない場合があります。
集合演算、アクセス制御、テストのアサーション、SQLの`WHERE`条件へ翻訳できるため、コードでは数学的仕様と実行意味の差を境界条件として記録します。

### 3つの代表的な対立軸

#### 対立軸1: 古典論理を基準にするか構成的論理を基準にするか

立場A：古典論理を採用し、命題は真か偽のいずれかであり、排中律（PまたはPの否定が成り立つ法則）や背理法を一般に使います。

立場Aの最も強い主張：数学的対象の存在を、実際の構成手順を示さずに理論全体の推論として扱えるため、簡潔で強力な定理と既存の数学との互換性を得られます。

立場B：構成的論理を採用し、存在を主張するなら、その対象を作る方法や計算可能な証拠を示すことを重視します。

立場Bの最も強い主張：存在証明から実行可能な構成やプログラムを取り出しやすく、証明が何を知っているかという情報を失いにくい点で、計算機上の検証に適します。

どの条件で選択が変わるか：既存の古典数学との接続や簡潔な理論展開が目的なら立場Aが有利で、証明からプログラムを抽出する場合、構成可能性が要件の場合、証拠の内容を保証したい場合は立場Bが有利です。
どちらが「正しいか」は未解決の好みではなく採用する論理体系の定義の問題であり、体系を選ぶ実務上の判断は別に残ります。

#### 対立軸2: 真理条件を中心に置くか証明可能性を中心に置くか

立場A：モデル、解釈、真理値表などの意味論を中心に置き、式がどの状況で真になるかを基準に妥当性を評価します。

立場Aの最も強い主張：仕様が表す条件を明確にでき、異なる証明手順や実装が同じ意味を持つかを比較できます。

立場B：公理、推論規則、導出、正規化などの証明論を中心に置き、式をどのような有限手順で導けるかを基準に評価します。

立場Bの最も強い主張：証明を検査可能な構造として扱え、証明支援系や型システムで機械的に検証し、場合によってはプログラムへ変換できます。

どの条件で選択が変わるか：仕様の意図やモデル間の比較を優先するときは立場Aを重くし、機械検査、証明の再利用、証明からの計算抽出を優先するときは立場Bを重くします。
完全性や健全性が成り立つ体系では両者を対応づけられますが、対応定理があることと、個々の証明を効率よく見つけられることは同じではありません。

#### 対立軸3: 二値論理を使うか多値または非古典論理を使うか

立場A：各命題を真か偽の二値で扱い、否定、論理積、論理和、含意を真理関数として定めます。

立場Aの最も強い主張：定義と実装が単純で、真理値表、ブール回路、通常の条件分岐、古典的な証明技法を直接利用できます。

立場B：未知、未定義、矛盾、確信度などを区別するため、多値論理や別の非古典論理を採用します。

立場Bの最も強い主張：データ欠損、センサーの不確実性、矛盾した知識、段階的な真偽を二値へ無理に潰さず、現実の情報状態を表現できます。

どの条件で選択が変わるか：入力が完全で失敗時の意味を明確に二分できるなら立場Aが扱いやすく、未観測と偽を区別する必要や矛盾を保持する必要があるなら立場Bを検討します。
多値化すれば意味が自動的に正確になるわけではなく、各値の意味、演算表、コード上の伝播規則を定義しない限り、二値より曖昧になる可能性があります。
