# Part 8　木構造

## 学習目標

- 木をグラフの特別な構造として定義できる。
- 根、親、子、葉、深さ、高さを図から読める。
- 二分木、完全二分木、二分探索木、ヒープを区別できる。
- 木構造がファイルシステム、DOM、構文解析、DB索引に使われる理由を説明できる。

## まず直感

木は、階層を表す構造です。

ファイルシステムでは、フォルダの中にファイルやフォルダがあります。

HTMLのDOMでは、要素の中に子要素があります。

組織図や分類体系も木に似ています。

グラフとして見ると、木は連結で閉路がなく、頂点n個に対して辺n-1本を持ちます。

## 正式な定義

**木**は、連結で閉路を持たない無向グラフです。

木から辺を一つ取り除くと非連結になり、木に辺を一つ追加すると閉路ができます。

頂点数が `n` の木の辺数は `n-1` です。

閉路を持たないが連結とは限らないグラフを**森**と呼びます。

連結グラフの全頂点を含む木を**spanning tree（全域木）**と呼びます。

全域木は、元のグラフから辺を一部だけ残して、全頂点を最小限の辺でつないだ構造です。

一つの頂点を**根**として選んだ木を根付き木と呼びます。

根から一つ辺を下った頂点を子、その反対を親と呼びます。

同じ親を持つ頂点同士を兄弟と呼びます。

親、祖父母のように根へ向かう途中の頂点を祖先、子や孫のように下にある頂点を子孫と呼びます。

子を持たない頂点が葉です。

根から頂点までの辺数を深さ、木の頂点の深さの最大値を高さと呼びます。

各頂点の子が高々2個の木を二分木と呼びます。

すべての内部頂点が0個または2個の子を持つ二分木を**完満二分木（full binary tree）**と呼びます。

すべての葉の深さが同じで、すべての内部頂点が2個の子を持つ二分木を**完全（perfect）二分木**と呼ぶことがあります。

「complete binary tree」は通常、最後の段以外が埋まり、最後の段が左詰めの**完全二分木**を指します。

日本語資料では「完全」がfull、perfect、completeのいずれかの訳に使われることがあるため、子の個数と最下段の並びを定義してから使います。

二分探索木（BST）は、各頂点について左部分木のキーが小さく、右部分木のキーが大きいという順序条件を持ちます。

ヒープは、親のキーが子以上（最大ヒープ）または子以下（最小ヒープ）になる完全二分木です。

完全二分木は配列に格納しやすく、0始まりの配列では頂点iの左子が`2i+1`、右子が`2i+2`、親が`(i-1)//2`です。

BSTは順序検索のための構造ですが、ヒープは根の最小値または最大値をすばやく取り出すための構造です。

## 最小の具体例

```text
          8        深さ0
        /   \
       3     10     深さ1
      / \      \
     1   6      14  深さ2
```

根は8、8の子は3と10、1と6と14は葉です。

高さは2です。

BSTの条件は、8より小さい3が左、大きい10が右にあり、3の子1と6も条件を満たすことです。

根付き木の用語をこの図に当てはめると、3と10は8の子であり、3と10は兄弟です。

1、6、14は葉で、1の深さは2、10の高さは1、根8の高さは2です。

## 走査

木の全頂点を処理する順序に、前順、中順、後順、レベル順があります。

```text
preorder(u):   u → left → right
inorder(u):    left → u → right
postorder(u):  left → right → u
level-order:   深さの小さい順
```

BSTを中順走査すると、キーが昇順に並びます。

後順走査は、子の処理を終えてから親を処理するため、ディレクトリの容量計算に向いています。

## 手計算

上の木を走査します。

```text
前順: 8, 3, 1, 6, 10, 14
中順: 1, 3, 6, 8, 10, 14
後順: 1, 6, 3, 14, 10, 8
```

完全二分木で高さhなら、レベルdの頂点数は最大 `2^d` です。

高さ2までの最大頂点数は `1+2+4=7` です。

全域木の手計算では、元のグラフの全頂点を残し、閉路を作る辺を一つずつ除きます。

```text
元のグラフ: A---B
            | \/|
            C---D
```

辺`AB, AC, BC, BD, CD`から`AB, BC, BD`だけを残すと、全頂点を含み、辺数が`4-1=3`で閉路のない全域木になります。

最小全域木では、辺の重みを比較しながらこの選択を行います。

最小ヒープ`[2, 4, 5, 9, 6]`から最小値2を取り出す場合、最後の6を根へ移して`[6, 4, 5, 9]`とします。

6と子4を比較して交換し、`[4, 6, 5, 9]`とすれば、親が子以下という条件が回復します。

## 証明の設計と完全な証明

命題「BSTの中順走査は昇順になる」を示します。

### 証明の段階

1. BSTの順序条件を、左部分木・根・右部分木の三つに分けます。
2. 空木または一頂点の木を基底の場合として確認します。
3. 左右の部分木について命題が成り立つと仮定します。
4. 中順走査が「左部分木、根、右部分木」の順であることを使います。
5. 左の全キーが根より小さく、右の全キーが根より大きいことから、全体の列が昇順だと結論します。

このように、証明の段階では、使う定義、基底の場合、帰納の仮定、結論への接続を分けて書きます。

### 使う定義

BSTでは、左部分木のすべてのキーが根より小さく、右部分木のすべてのキーが根より大きいとします。

### 方法の候補

木の高さに関する帰納法が自然です。

### 完全な証明

空木または一頂点の木では、中順走査はすでに昇順です。

根をr、左部分木をL、右部分木をRとします。

帰納法の仮定より、Lの中順走査は昇順、Rの中順走査も昇順です。

BSTの性質より、Lのすべてのキーはrより小さく、Rのすべてのキーはrより大きいです。

したがって `Lの走査 → r → Rの走査` は全体として昇順です。

なお、木そのものについても、頂点数nの木の辺数が`n-1`になることを、葉を一つずつ取り除く帰納法で示せます。

頂点が1つのとき辺は0本です。

頂点数nの木には葉が少なくとも一つあります。

実際、葉が一つもないとすべての頂点の次数が2以上になり、頂点をたどり続けたとき有限性から頂点を再訪して閉路が生じます。

葉とその接続辺を取り除くと、残りは頂点数n-1の木です。

帰納法の仮定で残りの辺数はn-2本なので、元の木の辺数はn-1本です。

## ヒープと優先度付きキュー

最小ヒープでは、根が全要素の最小値です。

最小要素を取り出した後、最後の要素を根へ移し、子との比較で下へ移動させます。

挿入と削除は高さに比例し、完全二分木の高さが `O(log n)` なので、通常 `O(log n)` です。

優先度付きキューは、タスクの優先度順処理やDijkstra法に使われます。

## Python例

```python
class Node:
    def __init__(self, key, left=None, right=None):
        self.key = key
        self.left = left
        self.right = right

def inorder(node):
    if node is None:
        return []
    return inorder(node.left) + [node.key] + inorder(node.right)

root = Node(8, Node(3, Node(1), Node(6)), Node(10, None, Node(14)))
assert inorder(root) == [1, 3, 6, 8, 10, 14]
```

再帰の計算量は頂点を一度処理するため `O(n)`、再帰の深さは木の高さhです。

```python
import heapq


def bst_search(node, key):
    while node is not None:
        if key == node.key:
            return True
        node = node.left if key < node.key else node.right
    return False


heap = [5, 2, 7, 9, 6]
heapq.heapify(heap)
heapq.heappush(heap, 1)
assert heapq.heappop(heap) == 1
```

BST探索は高さhに対して`O(h)`で、平衡に近ければ`O(log n)`、一方向に偏れば`O(n)`です。

ヒープの挿入と最小値の取り出しは`O(log n)`、最小値の参照は`O(1)`です。

## よくある誤解

- 二分木は各頂点の子が高々2個というだけで、BSTとは限りません。
- 完全二分木と完全にバランスした木の用語は文脈で異なる場合があります。
- BSTの探索時間は高さに依存し、偏ると `O(n)` になります。
- ヒープは全体が完全に整列している構造ではありません。
- 木の根を変えると、親子関係や深さは変わりますが、無向グラフとしての木は同じです。

## コンピュータ科学との関係

- ファイルシステム：ディレクトリとファイルの包含関係。
- DOM：HTML要素の親子関係。
- 構文解析：ソースコードを構文木へ変換。
- DB索引：B木などで探索範囲を狭める。
- 決定木：条件分岐を根から葉へ進む分類器。
- ヒープ：優先度の高い要素を効率よく取り出す。

## 演習問題

### ★ 基本

1. 根付き木で、根の深さを答えてください。
2. 上の木の高さと葉を答えてください。

### ★★ 標準

3. 上の木の前順、中順、後順を求めてください。
4. 高さ3の完全二分木の最大頂点数を求めてください。

### ★★★ 応用

5. 昇順に並んだキーを順番にBSTへ挿入すると木が偏る理由を説明してください。
6. ヒープから最小値を削除する手順を、5要素の例で示してください。

### ★★★★ 発展

7. ファイルシステムの容量計算に後順走査が向く理由を、子と親の計算順序で説明してください。

## 解答と思考プロセス（詳しい解答）

1. 根から根へは辺を一つも通らないので、根の深さは0です。
   深さは頂点の個数ではなく、根からその頂点までの辺数で数える点に注意します。
2. 図の子を持たない頂点は1、6、14なので、これらが葉です。
   根8から最も遠い葉までの経路は`8→3→1`または`8→10→14`で、辺数は2です。
   したがって木の高さは2です。
3. 前順は「自分、左、右」なので、8を処理してから左部分木`3,1,6`、右部分木`10,14`を処理し、`8,3,1,6,10,14`です。
   中順は「左、自分、右」なので、`1,3,6,8,10,14`です。
   後順は「左、右、自分」なので、`1,6,3,14,10,8`です。
   中順が昇順であることは、この木がBSTの順序条件を満たすことの確認にもなります。
4. 高さ3の完全二分木では、深さ0から3までの各層の最大頂点数が`1,2,4,8`です。
   合計は `1+2+4+8=15`なので、最大頂点数は15です。
5. 昇順のキーを挿入すると、最初のキーより大きい値が連続して右子になります。
   例えば1、2、3、4を順に挿入すると、1の右に2、2の右に3、3の右に4という一本の鎖になります。
   頂点数nのとき高さは`n-1`となり、BST探索の計算量は`O(h)=O(n)`です。
6. 例えば`[2,4,5,9,6]`から2を削除します。
   最後の6を根へ移して`[6,4,5,9]`とし、6と子4・5を比較します。
   小さい子4と交換して`[4,6,5,9]`とすると、親が子以下になり最小ヒープが回復します。
   交換は木の高さ以下の回数なので、計算量は`O(log n)`です。
7. フォルダの容量は、直下のファイルだけでなく子フォルダの容量も含みます。
   そのため、子フォルダの計算を先に終え、結果を親フォルダへ返してから親の容量を確定する必要があります。
   後順走査は「すべての子を処理してから親を処理する」ため、この依存関係に一致します。

## 専門家の見方

### このセクションの読み方

ここでは、木を「階層らしい図」としてだけでなく、閉路を持たないグラフ、不変条件を持つ探索構造、記憶装置上の配置として捉える。

「多くの専門家が共有する共通土台」は木の定義や順序条件を指し、「代表的な対立軸」は高さ、入出力の単位、メモリ階層、更新コストの違いから生じる。

### 5つの中核的なメンタルモデル

#### 1. 木は、少ない辺で全体をつなぐ構造である

定義：木は連結で閉路を持たない無向グラフであり、頂点数が `n` なら辺数は `n-1` である。

境界条件：根を選んだ時点で親子や深さが定まるが、根を選ばない無向木には本来の上下関係はない。

他章との接続：グラフ章の全域木は、一般グラフから閉路を除いて全頂点を残す構造であり、木の定義を最小接続として利用する。

コードや現実のモデル化への意味：組織、ファイル、構文、分類を木で表すとき、本当に一つの親だけを持つのか、共有や循環がないのかを先に検査する。

#### 2. 根付き木は、依存関係と処理順を表す

定義：根付き木では、親が先に必要な処理と、子を先に必要とする処理を、前順や後順などの走査順で表現できる。

境界条件：子の計算が親の計算に依存するなら後順が自然だが、木が共有部分を持つDAGになると、同じ部分を重複処理しない設計が必要になる。

他章との接続：再帰章の呼び出しスタックは木の深さをたどり、グラフ章のDFSは木を作りながら一般グラフを探索する。

コードや現実のモデル化への意味：構文木の評価、フォルダ容量の集計、UI階層の描画では、親を処理する時点を依存関係から決める。

#### 3. 木の高さが、探索と更新のコストを支配する

定義：根から最も深い葉までの辺数を高さといい、親子を一方向にたどる処理は通常 `O(h)` で評価される。

境界条件：頂点数が同じでも、鎖状の木は高さが `n-1` になり、各操作が全頂点に近づくことがある。

他章との接続：完全二分木の高さは `O(log n)` であり、二分探索木の探索計算量を高さで表す理由になる。

コードや現実のモデル化への意味：検索の平均時間だけでなく最悪時の高さ、再帰スタック、キャッシュミス、更新後の形を測定対象にする。

#### 4. 木の名前より、不変条件がデータ構造を決める

定義：BSTは左部分木と右部分木のキー順序を、ヒープは親子間の優先度順序を不変条件として持つ。

境界条件：BSTは最小値を根に置く構造ではなく、ヒープは全要素の完全な順序を保持しないため、両者の操作保証は交換できない。

他章との接続：BSTの中順走査は整列列を作り、ヒープは優先度付きキューやDijkstraの未確定距離の管理へつながる。

コードや現実のモデル化への意味：検索、最小値取得、範囲走査、挿入、削除のどれを保証したいかを先に決め、適合する不変条件だけを実装する。

#### 5. 木は論理構造と物理配置を分けて設計する

定義：ポインタで子を参照する木と、添字で親子を計算する配列木は、同じ論理的な木を異なるメモリ配置で表せる。

境界条件：配列表現は完全二分木のように空きが少ない場合に効率的だが、偏った木では空き要素や移動コストが増える。

他章との接続：ヒープは完全二分木を配列へ置く例であり、データベースのB木やB+木は外部記憶のブロック単位を意識した索引である。

コードや現実のモデル化への意味：ポインタの追跡回数だけでなく、キャッシュ局所性、ディスク読み出し回数、更新時の移動、永続化形式を含めて設計する。

### 3つの代表的な対立軸

#### 対立軸1: 非平衡BSTと平衡化された探索木

この対立は、更新時の回転や管理情報のコストを払って最悪高さを抑えるか、構造管理を簡単にして入力依存の高さを許すかという違いである。

立場A：単純なBSTで、キーの比較だけを使って挿入と探索を行う。

立場Aの最も強い主張：実装が小さく、更新の定数倍コストが低く、入力がほぼランダムで高さが十分小さいなら、平衡化の管理を追加しなくてよい。

立場B：AVL木や赤黒木などの平衡化された探索木を使う。

立場Bの最も強い主張：回転（部分木の形を保ちながら辺を付け替える操作）と高さの規則で、探索や更新の最悪計算量を `O(log n)` に抑え、偏った入力による性能崩壊を防げる。

どの条件で選択が変わるか：入力順が予測できない、最悪遅延を保証したい、長期間更新するなら平衡化を選び、データが静的、分布が管理されている、または単純さと更新定数が重要なら単純BSTを選ぶ。

#### 対立軸2: 二分木の索引とブロック型のB木またはB+木

この対立は、比較回数を少なくするか、外部記憶の読み出し回数を少なくするかという計算機メモリ階層の違いである。

立場A：二分探索木やその平衡化版で、一回の比較ごとに一つの子へ進む。

立場Aの最も強い主張：主記憶上のデータでは実装が直接的で、順序検索や更新を細かい単位で扱いやすく、ノードごとの柔軟な構造を保てる。

立場B：B木やB+木で、一つのノードに多数のキーと子をまとめる。

立場Bの最も強い主張：ディスクやSSDのブロック読み出しを一回で多くのキー比較に使い、木の高さと高価なI/O（外部記憶との入出力）回数を抑えられる。

どの条件で選択が変わるか：主記憶中心で細かな更新と柔軟なノード操作が必要なら二分木を選び、データ量が大きくブロックI/Oや範囲走査が支配的ならB木やB+木を選ぶ。

#### 対立軸3: ポインタ配置と配列配置

この対立は、木の形を柔軟に変更するか、連続メモリと添字計算による局所性を活かすかという物理配置と更新コストの違いである。

立場A：各ノードが子へのポインタを持つ形で配置する。

立場Aの最も強い主張：不規則な木でも空き領域を作りにくく、挿入、削除、部分木の移動をポインタの付け替えで実装しやすい。

立場B：完全二分木を配列へ連続配置し、子と親を添字で計算する。

立場Bの最も強い主張：ポインタをたどる間接参照を減らし、連続メモリの局所性を活かして、ヒープのような形では少ない管理領域で高速に走査できる。

どの条件で選択が変わるか：形が変わりやすい、空の子が多い、部分木の共有や永続参照が必要ならポインタ配置を選び、完全性が保たれ、末尾への追加と優先度操作が中心なら配列配置を選ぶ。

木の最適な平衡化方式や物理配置は、更新と検索の比率、最悪遅延、メモリ階層、永続化方式で変わるため、理論上の一つの正解と実務上の選択を同一視できない。

### 理解の深さを見分ける10の質問

1. 頂点数が `n` の連結グラフで辺数が `n-1` なら木だといえる理由を、連結条件を外した反例とともに説明できるか。

2. 根を別の頂点へ移したとき、木そのものは変わらないのに深さ、親子関係、走査順のどれが変わるか。

3. ある木の高さが `n-1` になる入力順を作り、BST探索が `O(log n)` ではなく `O(n)` になる過程を説明できるか。

4. BSTの中順走査が昇順になる条件を、重複キーを許す場合の規則まで含めて言い換えられるか。

5. 同じ木をBSTと最小ヒープの両方として使えるかを、順序不変条件を比較して判断できるか。

6. 昇順キーを大量に挿入するサービスで、単純BST、AVL木、赤黒木のどれを選ぶかを、更新回数、探索遅延、実装コストから提案できるか。

7. ファイル容量の集計が後順走査に対応する理由を、親の値が子の値に依存する計算として漸化的に書けるか。

8. 完全二分木を配列に置く方式が、同じ配列方式でも偏ったBSTに向かない理由を、空き領域と添字計算で説明できるか。

9. 主記憶上の探索とデータベースの大規模な範囲検索で、二分木とB+木の選択が変わる理由を、比較回数ではなくI/O単位から説明できるか。

10. 木を現実の分類体系へ変換するとき、一つの項目が複数の親を持つ場合や循環参照がある場合に、木のモデルを維持するかDAGや一般グラフへ変えるかを、業務上の意味とアルゴリズムの要件から判断できるか。
