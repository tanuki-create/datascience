# LeetCode実行ログ

このファイルは、計画に対する実行状況を日ごとに記録する。

## 記録ルール

- 問題を提示しただけでは、ユーザーが解いたとは扱わない。
- ユーザーが実際に解いたか不明な場合は、`user_status` を `unconfirmed` とする。
- 解法や解説を提示したかどうかと、ユーザーが解けたかどうかを分けて記録する。
- 同じ問題を再提示しないため、問題IDを一意に管理する。
- カバレッジ問題は、深く学ぶ3問と重複させない。

## 状態の意味

| 項目 | 意味 |
|---|---|
| `planned` | 計画上、担当日に割り当てた |
| `presented` | 問題文・要約・リンクを提示した |
| `attempted` | ユーザーが自力で考えた |
| `solved` | ユーザーが自力でAcceptedした |
| `editorial` | 解説を確認して実装した |
| `revisit` | 後日もう一度解く |
| `unconfirmed` | ユーザーの実行状況が未確認 |
| `blocked` | Premiumや環境などで進められない |

## 実行後に追記する項目

毎日の終了時に、次を更新する。

1. 実際に提示した問題IDを追加する。
2. ユーザーが自力で解けたかを確認する。
3. `solved`、`editorial`、`revisit` のいずれかに更新する。
4. Easy、Medium、Hardの実績数を更新する。
5. 未達分を翌日以降のカバレッジ枠へ移す。
6. 翌日の主テーマと深掘り3問を確定する。

## 「今日の問題」からの運用

ユーザーが「今日の問題」と言った場合、次の順で実行する。

1. Asia/Tokyoの現在日付を取得する。
2. `three_month_plan_2026-08-17.md` からDayと主テーマを取得する。
3. このログから、提示済み・完了済みの問題を除外する。
4. Easy、Medium、Hardを1問ずつ、深掘り用として提示する。
5. 残りのカバレッジ問題を、短い日本語の問題文要約付きで提示する。
6. 各問題に公式LeetCodeリンクを付ける。
7. 解法や答えは、ユーザーが求めるまで表示しない。

## カバレッジ問題の出力形式

カバレッジ問題は、全文転載ではなく、次の形式で提示する。

```text
### 問題番号. タイトル — 難易度

問題の短い日本語要約。

入力・出力の要点。
制約の要点。
主なテーマまたはタグ。

LeetCode公式リンク
```

カバレッジ問題の解法・コード・詳細解説は、ユーザーが指定した問題だけに対して提示する。
