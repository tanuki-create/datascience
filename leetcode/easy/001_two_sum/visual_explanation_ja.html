Two Sum（2数の和）

基本例を一段階ずつたどり、和を求める問題を1回の走査と 高速な検索に置き換える過程を確認します。

問題の要点

整数配列 nums と整数 target が与えられます。 値の合計が target になる2つの異なる要素の インデックス（配列内の位置を表す番号）を返します。 同じインデックスを2回使うことはできず、入力には有効な組がちょうど1つ存在します。

知っておきたい用語

補数（complement）
現在の値との合計を目標値にするために必要な値です。 target - current value で求めます。
ハッシュマップ
キーと値を対応付けるデータ構造です。 Python の dict はハッシュマップであり、通常は 入力サイズにかかわらず平均的な処理量が変わらない定数時間でキーを検索できます。
インデックス
配列内の位置を表す番号です。 Python は0始まりなので、最初の要素のインデックスは 0 です。
定数時間
入力サイズが増えても、平均的な処理量が増えない計算量です。 O(1) と表します。

アルゴリズムと正しさ

擬似コード

空のハッシュマップ seen を作る

nums の各 index と number について:
    complement = target - number

    complement が seen に存在する場合:
        return [seen[complement], index]

    seen に number -> index を保存する

正しく動作する理由

各要素を確認する直前には、処理済みの異なる値ごとに、 その値が以前に現れた位置のインデックスが seen に保存されています。 同じ値が複数回現れても、以前のインデックスは1つあれば十分です。

  • 補数が存在する場合、保存済みのインデックスと現在のインデックスは、 合計が目標値になる2つの異なる要素を指します。
  • 補数が存在しない場合、現在の値を保存して後続の確認に利用できるようにします。
  • 保存前に補数を確認することで、現在の要素をそれ自身と組み合わせることを防ぎます。 この順序でも、重複する値は正しく処理できます。

計算量

方法 時間計算量 追加領域 意味
すべての組を調べる O(n²) O(1) 処理量は配列長の2乗に比例して増える可能性があります。
ハッシュマップ走査 平均 O(n) O(n) 各要素を1回ずつ調べ、最大 n 個のキーを保存します。

Big O 記法は、入力サイズ n に応じて 処理量や追加メモリがどのように増えるかを表します。 O(n) は線形増加を意味します。 追加領域の O(1) は、入力サイズが増えても必要な追加メモリが増えないことを意味します。

基本例: nums = [2, 7, 11, 15]、 target = 9。
