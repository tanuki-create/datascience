# Webセキュリティ用語動画テンプレート要件

## 目的

Webセキュリティ用語一覧を、HyperFrames/HTMLで量産できる1080x1920縦動画に変換するためのテンプレート要件を定義する。各動画は20秒前後で、音声がなくても日本語字幕と図解だけで意味が伝わることを前提にする。

## 基本仕様

- 解像度: 1080x1920
- アスペクト比: 9:16
- 想定尺: 18-22秒
- 言語: 日本語
- 字幕: 常時表示またはシーンごとの固定表示
- 量産方式: 1つのテンプレートに用語データを差し替えて複数動画を生成
- 実装方式: HyperFrames/HTML/CSS/JavaScript
- 音声: 任意。音声なしでも理解できる画面構成を必須にする

## 1本あたりの必須構成

### 0.0-2.5秒: 用語提示

- 画面上部にカテゴリラベルを表示する。
  - 例: 認証、攻撃手法、通信、ブラウザ、脆弱性、暗号
- 中央に用語名を大きく表示する。
- 英語略語や正式名称がある場合は併記する。
  - 例: XSS / Cross-Site Scripting
- 用語の読みが難しい場合はふりがな相当の補助テキストを置く。

### 2.5-6.5秒: 一言定義

- 「何を指す言葉か」を1文で示す。
- 定義文は最大2行、1行あたり18文字前後を目安にする。
- 抽象語だけで終わらせず、対象を明示する。
  - 悪い例: 危険な攻撃です
  - 良い例: 入力欄に悪意あるスクリプトを混ぜる攻撃

### 6.5-12.5秒: 図解

- 用語ごとに、最低1つの関係図を表示する。
- Webセキュリティ用語に向く図解パターンをテンプレート化する。
  - クライアント、ブラウザ、サーバ、DB、攻撃者、正規ユーザーの関係図
  - リクエスト/レスポンスの矢印図
  - 入力値が処理される流れ
  - 信頼境界を越えるデータの流れ
  - 正常系と攻撃系の比較
- 図解内のラベルは短くし、詳細は字幕側で補う。
- 矢印は意味別に使い分ける。
  - 通常通信: 実線
  - 攻撃/改ざん: 赤系または警告色の線
  - 防御/検証: 緑系またはチェック付きの線

### 12.5-16.5秒: 一個下のレイヤー

- すべての用語で、表面的な説明だけでなく「一個下のレイヤー」を必ず出す。
- 表示する内容は、次のいずれかを必須にする。
  - 具体的にどのデータが問題になるか
  - どの処理段階で起きるか
  - どの信頼境界を越えるか
  - ブラウザ、サーバ、DB、Cookie、ヘッダー、セッションなどのどこに関係するか
  - 攻撃が成立する条件
- 例: CSRFなら「ログイン済みCookieが自動送信される」、SQLインジェクションなら「入力値がSQL文として解釈される」。

### 16.5-20.0秒: 覚え方/防御の着地

- 最後に1つだけ覚えるポイントを表示する。
- 防御がある用語では、代表的な防御策を1つに絞って示す。
- 由来や語の展開がある場合はここまでに必ず出す。
  - 略語: 正式名称と直訳
  - 日本語訳: 直訳と実務上の意味
  - 似た用語との差分: 1点だけ

## 画面レイアウト要件

### セーフエリア

- 重要テキストは左右80px以上、上下120px以上の内側に配置する。
- 下部字幕は画面下端から180px以上離す。
- SNS UIやプレイヤーUIに隠れやすい右下、左下には重要情報を置かない。
- 用語名、定義、字幕、図解ラベルが重ならないよう、シーン単位で固定領域を分ける。

### 推奨領域

- 上部: カテゴリ、進行バー、短い補助ラベル
- 中央: 用語名または図解
- 下部: 日本語字幕、要点、注意点
- 背景: 薄いグリッド、通信線、抽象的な画面枠など、図解を邪魔しない要素に限定する。

### タイポグラフィ

- 用語名: 72-96px
- 日本語定義: 44-56px
- 字幕: 40-48px
- 図解ラベル: 30-38px
- 補助ラベル: 24-30px
- 文字間隔は原則0にする。
- 長い英単語、URL、ヘッダー名、略語は自動縮小または改行ルールを持つ。
- 最小文字サイズは24pxを下回らない。

### 色と状態表現

- 通常通信、危険、保護、注目の4状態を色で分ける。
- 色だけに依存せず、アイコン、線種、ラベルも併用する。
- 背景と本文のコントラストを確保する。
- 赤系は攻撃や危険に限定し、常時装飾には使わない。

## 量産データ要件

各動画は、次のような1用語1レコードの構造データから生成できること。

```json
{
  "term": "XSS",
  "reading": "クロスサイトスクリプティング",
  "expanded": "Cross-Site Scripting",
  "category": "攻撃手法",
  "oneLineDefinition": "入力欄に悪意あるスクリプトを混ぜる攻撃",
  "originOrBreakdown": "Cross-Siteは別サイトをまたぐ意味、Scriptingはスクリプト実行を指す",
  "lowerLayer": "ブラウザがHTMLとして解釈した入力値の中でスクリプトが動く",
  "diagramType": "request-flow",
  "actors": ["攻撃者", "ブラウザ", "Webサーバ"],
  "flow": [
    {"from": "攻撃者", "to": "Webサーバ", "label": "悪意ある入力", "risk": true},
    {"from": "Webサーバ", "to": "ブラウザ", "label": "HTMLとして返す", "risk": true}
  ],
  "keyPoint": "入力をそのままHTMLに混ぜない",
  "defense": "出力エスケープ"
}
```

必須フィールド:

- `term`
- `category`
- `oneLineDefinition`
- `originOrBreakdown`
- `lowerLayer`
- `diagramType`
- `keyPoint`

任意フィールド:

- `reading`
- `expanded`
- `actors`
- `flow`
- `normalFlow`
- `attackFlow`
- `defense`
- `relatedTerms`

## 図解テンプレート種別

- `request-flow`: ブラウザとサーバ間のリクエスト/レスポンス
- `trust-boundary`: 信頼できない入力が境界を越える流れ
- `normal-vs-attack`: 正常系と攻撃系の左右比較
- `stack-layer`: ブラウザ、HTTP、アプリ、DBなどの層構造
- `token-cookie`: Cookie、セッション、トークン、ヘッダーの関係
- `input-to-execution`: 入力値が処理または実行に変わる流れ
- `crypto-chain`: 鍵、平文、暗号文、署名、検証の関係

各テンプレートは同じデータ構造でレンダリングできる範囲を明確にし、例外的な用語だけ個別HTMLに逃がす設計にしない。

## 字幕要件

- 字幕は音声の補助ではなく、単体で説明が成立する本文として設計する。
- 1字幕は最大2行。
- 1行は18-22文字程度を上限にする。
- 字幕の表示時間は最低1.8秒を確保する。
- 用語名、正式名称、由来、一個下のレイヤー、覚えるポイントの字幕を必ず含める。
- 専門語が2つ以上同時に出る字幕は避ける。
- 字幕背景は半透明帯または高コントラストの固定領域にする。

## アニメーション要件

- アニメーションは理解を助ける用途に限定する。
- 矢印は流れの順に出す。
- 攻撃箇所は点滅ではなく、短いハイライトや囲みで示す。
- テキストは過度に動かさず、読める時間を確保する。
- 画面遷移は200-400ms程度に抑え、説明時間を削らない。
- 同じシリーズ内で登場順と動きの意味を統一する。

## レンダリング検証観点

### レイアウト

- 1080x1920で文字がはみ出していない。
- 長い用語名、正式名称、英単語、URL風文字列でも自動改行または縮小される。
- 字幕がセーフエリア内に収まっている。
- 字幕と図解ラベルが重ならない。
- 図解の矢印、ノード、ラベルが画面外に出ない。
- 重要情報が下部UI想定領域に被らない。

### 内容

- 用語の展開、由来、または分解説明が必ず出ている。
- 一個下のレイヤーが必ず出ている。
- 定義、図解、下位レイヤー、覚えるポイントが矛盾していない。
- 防御策を出す場合は、用語の説明より目立ちすぎていない。
- 似た用語との差分を扱う場合は1点だけに絞られている。

### 量産性

- 同一テンプレートに別データを差し替えて複数動画を生成できる。
- 同一データで複数回レンダリングしてもタイミング、改行、配置が安定している。
- 必須フィールド欠落時にレンダリング前の検証で失敗できる。
- 用語ごとの個別CSS追加なしで成立する。
- 図解テンプレートごとの入力データがスキーマで検証できる。

### 音声なし理解

- ミュート状態で見ても、用語の意味、起きる場所、覚えるポイントがわかる。
- ナレーションにしか存在しない情報がない。
- 画面上の字幕と図解だけで説明の順序が追える。
- BGMや効果音に依存した強調がない。

### 日本語可読性

- 漢字が多い字幕は短く分割されている。
- 英語略語には正式名称または日本語補足がある。
- 1画面に長文が集中していない。
- 読みづらい専門語は初出時に補助説明がある。

## 実装レビュー時のチェックリスト

- データスキーマに必須フィールドが定義されている。
- `originOrBreakdown` と `lowerLayer` が空文字で通らない。
- 1080x1920のスクリーンショット検証がある。
- 長文サンプルデータで文字はみ出し検証がある。
- 同じデータを2回レンダリングして差分が許容範囲内である。
- 複数用語を一括生成するスクリプトが同じテンプレートを使っている。
- 字幕安全領域を可視化するデバッグモードがある。
- 音声なしプレビューで意味が通ることをレビュー項目に含めている。
- 図解テンプレートごとの代表サンプルが少なくとも1件ある。
- 個別用語だけに依存するハードコードがない。

## 代表テストデータ

実装時は、短い用語、長い用語、英語略語、複数アクター、DBを含む用語を混ぜて検証する。

- XSS
- CSRF
- SQLインジェクション
- セッション固定攻撃
- Content Security Policy
- SameSite Cookie
- CORS
- パストラバーサル
- OAuth 2.0
- HSTS

## 受け入れ基準

- 1つのテンプレート実装から、最低5本の異なる用語動画を生成できる。
- すべての動画が18-22秒に収まる。
- すべての動画で、用語名、定義、由来または展開、一個下のレイヤー、覚えるポイントが表示される。
- すべての動画がミュート状態で理解できる。
- 文字はみ出し、字幕安全領域違反、図解重なりがない。
- レビュー担当者がスクリーンショットだけで主要な検証項目を確認できる。
