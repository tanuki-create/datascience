# 07. データ整形・欠損処理

欠損、重複、表記揺れは実務データでは避けられません。ここを丁寧に扱うほど、集計結果やモデルの信頼性が上がります。

## `dropna()`

- 基本の説明: 欠損値を含む行または列を削除します。
- 基本構文: `df.dropna(axis=0, how="any")`, `df.dropna(subset=[...])`
- 主な引数/指定:
  - `axis`: `0` または `"index"` は行を削除、`1` または `"columns"` は列を削除します。
  - `how`: `"any"` は1つでも欠損があれば削除、`"all"` は全て欠損の場合だけ削除します。
  - `subset`: 欠損を判定する対象列または行を限定します。
  - `thresh`: 欠損でない値が指定個数以上ある行・列だけ残します。
- 実用での使用場面: 必須項目が欠けた注文、日付がないログ、目的変数が欠けた学習データを除外します。
- 使用例:

```python
valid_sales = sales.dropna(subset=["quantity", "price"])
```

- 戻り値: 欠損条件に該当する行または列を除いた `DataFrame` または `Series`。
- よくある注意点:
  - 何も指定しないと、どこか1か所でも欠損がある行を削除します。必要以上にデータが減ることがあります。
  - `subset` を使って「必須列だけ」を判定対象にすると、業務意図に合いやすくなります。
  - 削除前後の行数を確認し、偏ったカテゴリや期間だけ消えていないか確認します。
- 関連メソッド: `fillna()`, `isna()`, `notna()`, `drop()`
- インパクト: 不完全なデータによる計算エラーを防げます。一方で削除しすぎるとサンプルが偏るため、削除件数の確認が重要です。

## `fillna()`

- 基本の説明: 欠損値を指定値で補完します。
- 基本構文: `df.fillna(value)`, `df.fillna({"col": value})`, `s.ffill()`, `s.bfill()`
- 主な引数/指定:
  - `value`: 補完に使う値、辞書、`Series`、`DataFrame` を指定します。
  - 前後方向の補完: 前方補完は `ffill()`、後方補完は `bfill()` を使います。
  - `limit`: 連続欠損を補完する最大数を指定します。
  - `axis`: 補完方向を指定します。
- 実用での使用場面: 数量欠損を0扱いにする、カテゴリ欠損を `"unknown"` にする、前回値で補完する場面で使います。
- 使用例:

```python
filled = sales.fillna({
    "quantity": 0,
    "product": "unknown",
})
```

- 戻り値: 欠損値を補完した `DataFrame` または `Series`。
- よくある注意点:
  - すべての欠損を一律に0で埋めると、平均や分布を大きく変えることがあります。
  - 文字列列、数値列、日付列で妥当な補完値は異なります。列ごとに辞書で指定するのが安全です。
  - 前方補完は時系列順に並んでいることが前提です。補完前に `sort_values()` や `sort_index()` を確認します。
- 関連メソッド: `dropna()`, `interpolate()`, `replace()`, `where()`, `combine_first()`
- インパクト: 欠損を残せない集計や機械学習処理に進めます。ただし補完値の意味を業務的に説明できる必要があります。

## `isna()`

- 基本の説明: 欠損値かどうかを真偽値で返します。
- 基本構文: `df.isna()`, `s.isna()`
- 主な引数/指定:
  - 引数は通常指定しません。
  - `pd.NA`, `np.nan`, `None`, `NaT` などが欠損として判定されます。
- 実用での使用場面: 欠損件数の確認、欠損行の抽出、欠損フラグ作成に使います。
- 使用例:

```python
missing_count = sales.isna().sum()
missing_rows = sales.loc[sales["quantity"].isna()]
```

- 戻り値: 元データと同じ形の真偽値 `DataFrame` または `Series`。
- よくある注意点:
  - 空文字 `""` や文字列 `"NA"` は自動では欠損扱いになりません。必要なら `replace()` などで事前に変換します。
  - 欠損でない値を調べる場合は `notna()` を使います。
  - 欠損率を見る場合は `df.isna().mean()` のように平均を取ると列ごとの割合を確認できます。
- 関連メソッド: `notna()`, `isnull()`, `notnull()`, `fillna()`, `dropna()`
- インパクト: 欠損の場所と量を定量化できます。欠損処理の方針を決める前に必ず確認したい項目です。

## `interpolate()`

- 基本の説明: 欠損値を前後の値から補間します。
- 基本構文: `s.interpolate(method="linear")`, `df.interpolate(axis=0)`
- 主な引数/指定:
  - `method`: `"linear"` が基本です。時系列インデックスでは `"time"` も使えます。
  - `axis`: 行方向または列方向の補間方向を指定します。
  - `limit`: 連続して補間する最大欠損数を指定します。
  - `limit_direction`: `"forward"`, `"backward"`, `"both"` で補間方向を指定します。
- 実用での使用場面: センサー値、時系列指標、連続的に変化する数値の欠損補完に使います。
- 使用例:

```python
ts = pd.Series([100, None, 130, None, 160])
filled_ts = ts.interpolate()
```

- 戻り値: 補間後の `DataFrame` または `Series`。
- よくある注意点:
  - 連続値の補間に向いており、カテゴリ、ID、イベント発生有無のような不連続値には向きません。
  - 先頭や末尾の欠損は、通常の線形補間だけでは埋まらない場合があります。
  - 時系列で `method="time"` を使う場合は、インデックスが日時型である必要があります。
- 関連メソッド: `fillna()`, `ffill()`, `bfill()`, `to_datetime()`, `resample()`
- インパクト: 時系列の連続性を保ちながら欠損を埋められます。カテゴリや不連続なイベント値には向きません。

## `duplicated()`

- 基本の説明: 重複行かどうかを真偽値で返します。
- 基本構文: `df.duplicated(subset=None, keep="first")`
- 主な引数/指定:
  - `subset`: 重複判定に使う列を指定します。複数列の組み合わせも指定できます。
  - `keep`: `"first"` は最初を重複扱いしない、`"last"` は最後を重複扱いしない、`False` は全ての重複行を `True` にします。
- 実用での使用場面: 注文ID、ユーザーID、日付と店舗の組み合わせなど、重複してはいけないデータを確認します。
- 使用例:

```python
duplicate_rows = sales.loc[sales.duplicated(subset=["date", "store", "product"])]
deduped = sales.drop_duplicates(subset=["date", "store", "product"])
```

- 戻り値: 各行が重複かどうかを示す真偽値 `Series`。
- よくある注意点:
  - 完全一致の重複と、業務キー上の重複は別です。多くの場合は `subset` で業務キーを明示します。
  - `keep=False` を使うと、重複グループに含まれる全行を確認できます。
  - 重複を削除する前に、どの行を残すべきかを日付や更新時刻で決めます。
- 関連メソッド: `drop_duplicates()`, `value_counts()`, `groupby()`, `nunique()`
- インパクト: 二重計上を防げます。売上や件数の集計では特に影響が大きい確認項目です。
