# 09. 次元削減、埋め込み、表現学習

## 現場の問い

次元削減は、単に列数を減らす技術ではありません。ノイズを減らす、可視化する、検索しやすくする、下流モデルが扱いやすい表現を作るための道具です。

## 直感

PCA は、データのばらつきが大きい方向を見つけて圧縮します。埋め込みは、テキスト、画像、ユーザー、商品などをベクトル空間に置き、近さで意味的な類似を扱えるようにします。

ただし、低次元表示は現実をそのまま写す地図ではありません。可視化で近いからといって、業務上も同じとは限りません。

## 最小限の数式

PCA は、データの分散をよく保つ方向へ射影します。

```text
z = W^T x
```

`W` は主成分方向、`z` は低次元表現です。

## 実装で見るべきログ・指標

- explained variance ratio。
- 次元削減前後の下流性能。
- 可視化の seed やパラメータ依存。
- embedding の近傍例。
- 検索での recall / latency。

## よくある失敗

- t-SNE / UMAP の図をクラスタの証拠として過信する。
- PCA を全データで fit してから分割する。
- embedding の近さを因果や好みの証拠として扱う。
- 圧縮で重要な rare pattern を消す。
- 可視化の見栄えだけでモデル改善を判断する。

## 実務メモ

表データでは、次元削減は説明性を落とすことがあります。一方で、画像・テキスト・ログ・検索では、埋め込みがシステム設計の中心になります。目的が可視化、圧縮、検索、ノイズ除去、特徴量作成のどれなのかを先に決めます。

## 演習

1. PCA の explained variance が高いのに下流性能が落ちる理由を考える。
2. embedding 近傍検索で、近いが不適切な例をどう検出するか設計する。
3. 次元削減を fit する位置を pipeline の中で説明する。
