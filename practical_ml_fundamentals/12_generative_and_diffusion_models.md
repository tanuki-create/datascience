# 12. 生成モデルとDiffusion

## 現場の問い

生成モデルは、新しいデータを作る、欠損を補う、候補を広げる、表現を学ぶために使えます。ただし、生成品質、制御性、権利、安全性、推論コストを同時に考える必要があります。

## 直感

VAE は潜在空間からデータを生成する発想、GAN は生成器と識別器の競争、Diffusion はノイズを少しずつ除去してデータを作る発想です。

Diffusion は高品質な生成に強い一方、サンプリングステップが多いと遅くなります。条件付けや guidance によって出力を制御できますが、制御を強めると多様性や自然さが落ちることがあります。

## 最小限の数式

Diffusion の直感:

```text
forward: clean data -> noisy data
reverse: noisy data -> clean-like data
```

学習では、加えたノイズやスコアを推定するようにネットワークを訓練します。

## 実装で見るべきログ・指標

- サンプリングステップ数とレイテンシ。
- seed によるばらつき。
- 条件入力への忠実度。
- 不適切出力の頻度。
- 人手評価の基準。
- 生成物の保存・再現・利用範囲。

## よくある失敗

- 見た目の良い cherry-pick だけで品質判断する。
- 生成物の権利・出所・利用条件を確認しない。
- prompt や seed を記録せず再現できない。
- 生成品質と業務上の有用性を混同する。
- 安全性レビューなしに外部公開する。

## 実務メモ

生成モデルの評価は、単純な accuracy では済みません。品質、多様性、条件忠実度、安全性、コスト、遅延、再現性を分けて評価します。業務で使うなら、出力をそのまま採用するのか、人が確認するのか、候補生成だけに使うのかを明確にします。

## 演習

1. 画像生成を業務で使う場合の禁止条件を 5 つ書く。
2. sampling steps を増やすことの利点と欠点を説明する。
3. 生成モデルを「候補作成」に限定する設計例を作る。
