# 13. 評価、失敗解析、MLOps

## 現場の問い

モデルは作って終わりではありません。本番に出した後、データ、利用者、業務ルール、上流システムが変わります。評価と運用は、モデルの寿命を管理する仕事です。

## 直感

オフライン評価は出荷前の試験です。オンライン評価は現場での実測です。MLOps は、コード、データ、モデル、評価、閾値、設定を再現可能にし、劣化したときに戻せるようにする仕組みです。

## 最小限の数式

分類指標の基本:

```text
precision = TP / (TP + FP)
recall    = TP / (TP + FN)
```

業務判断では、誤検知と見逃しのコストを含めます。

```text
expected_cost = FP * cost_fp + FN * cost_fn + operation_cost
```

## 実装で見るべきログ・指標

- offline metrics と online KPI。
- 入力分布、予測分布、欠損率、スキーマ違反。
- セグメント別性能。
- 閾値、モデル、特徴量、データのバージョン。
- ラベル到着後の性能再計算。
- rollback 手順と所要時間。

## よくある失敗

- AUC は高いが、実際に処理できる上位件数の precision が低い。
- 本番劣化時に、データ、特徴量、モデル、閾値、インフラのどれが変わったか分からない。
- 再学習で良くなった指標だけを見て、重要セグメントが悪化する。
- モニタリングがレイテンシとエラー率だけで、ML 固有の劣化を見ない。
- rollback するモデルと前処理の組み合わせが一致しない。

## 実務メモ

精度が落ちたと言われたら、最初にモデル構造を疑うのではなく、データを疑います。上流スキーマ変更、欠損増加、カテゴリ増加、タイムゾーン、サンプリング条件、ラベル遅延を確認します。

失敗解析は、誤りを一覧化し、パターンに名前を付ける作業です。名前が付くと、データ追加、特徴量追加、閾値調整、ルール併用、人手レビューなどの対応策を選べます。

3. 本番劣化時の調査順を、データ、特徴量、モデル、閾値、インフラに分けて書く。
